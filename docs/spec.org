* Outline

0. Design Goals and Philosophy
   - Ouro is a DSL for constructing and serialising CIDOC-CRM / Linked Art compliant JSON-LD knowledge graphs, written by curators rather than programmers.
   - Dynamic code, static output: a resilient, dynamically typed evaluation phase (~L.Expr~) with optional checked annotations, followed by a mandatory collapse into a strictly typed JSON-LD GADT (~I.Expr~).
   - Lexical scope with lazy, memoised bindings: declaration order never matters, every binding is evaluated at most once, and cycles are reported rather than looping.
   - Referential transparency: there are no side effects, no quoting and no recursion, so any expression can be replaced by its value.
   - Structural topology: the shape of the source is the shape of the JSON output.
   - No runtime: everything is resolved at compile time; the output is a static document.
   - Deterministic serialisation: a fold over the validated GADT, in source order.

* Design Goals

Ouro is a domain-specific language engineered for the ergonomic construction, validation and serialisation of CIDOC-CRM knowledge graphs, in particular Linked Art JSON-LD. It bridges human-readable data modelling and strict Semantic Web standards: a program that compiles produces well-formed JSON.

** Structural topology

Ouro code mirrors its output. A record ~(:key value ...)~ becomes a JSON object, a form of values ~(a b c)~ becomes a JSON array, and nesting carries through unchanged. Nothing appears in the output unless it is written as an attribute pair or an element; everything else either produces a value in place (calls, =case=, =get=, =let=) or disappears (=let= bindings, =defn=).

The rule of thumb is /structure is written, values are computed/: parentheses give the shape, and anything that is not an attribute pair or an element evaluates to a value in the position where it is written. The one construct that changes shape is =inlay=, which splices a record's attribute pairs (or an array's elements) into the surrounding one.

Ouro is still written as s-expressions, but it is no longer homoiconic in practice: quoting and =eval= were removed, so programs never manipulate code as data. The s-expression is kept for its other property, a uniform notation whose nesting is the nesting of the data.

** Referential transparency

Ouro has no side effects, no mutable state, no quoting and no recursion. Every expression can be replaced by its value without changing the program: ~((+ 2 4) 3)~ and ~(6 3)~ are the same array, match the same patterns and serialise identically. A property test checks this (~prop_substitution~ in =ScopingTest.hs=).

** Lexical scope, lazily

Every name means what it meant where it was written. To find what a name refers to, read
outward through the enclosing parentheses, never through the call stack.

- *Order independence:* the attribute pairs of a record and the bindings of a =let= can refer to each other in any order, like Scheme's =letrec=. Curators can write a graph in the order that reads best.

- *Call-by-need:* every binding (record attribute pair, =let= binding, function argument) is a promise, evaluated at most once and only when needed, in the scope it was written in. A chain of 40 bindings that each use the previous one twice compiles instantly (~prop_sharedChain~ in =ScopingTest.hs=).

- *Cycles are errors:* a binding that depends on itself is reported ("…references itself…"), never evaluated forever.

- *No hidden errors:* after the output is built, every promise it never needed is forced, so an error in an unused binding is still reported.

** No runtime

Ouro is a compiler, not an interpreter for a program that runs later. All names, calls and patterns are resolved at compile time; the result is a static JSON-LD document. There is no virtual machine, no I/O and no network access during compilation (see [[*6. Architectural Boundaries][Architectural Boundaries]]).

** Dynamic code, static output

Ouro is dynamically typed, with optional type annotations that are checked when values cross them. Its output is statically typed: everything is evaluated at compile time, so every document passes the verification gate before a byte is written.

Evaluation happens in a flexible, dynamically typed sandbox (~L.Expr~) in which errors are values. Before anything is serialised, the evaluated tree must pass the verification gate and is then collapsed into ~I.Expr~, a GADT indexed by JSON-LD kinds. Ouro is dynamic where curators write code and static where the output is produced.

The annotations are type tags, on an expression or in a function's [[*Functions: =defn=, =fn= and calls][signature]]. They behave like contracts (as in Racket) rather than static types: nothing is checked before evaluation, and an annotation on code that is never evaluated is never checked. When a check fails, the blame falls where it belongs: a bad argument is reported at the call, and a bad result at the function's body.

This is not gradual typing in the sense of Siek and Taha, where annotated code is checked statically and checks are inserted only at the boundary with untyped code.

** Errors for curators

Errors are part of the design, not an afterthought. Every surface node carries its ~SourcePos~, every error is reported with its position, a short message and a blurb that suggests a fix, and evaluation continues past an error so that one compile reports them all. Removed syntax is recognised and answered with its replacement (for example "'define' has been replaced by let.").

** Deterministic serialisation

Records keep their attribute pairs in source order (association lists, not maps), and the serialiser is a single fold over the frozen GADT. The same input always produces byte-identical output.

** The Ouro compilation pipeline

The flow from source to JSON is strictly linear (~Data.Ouro.compile~):

| Pass | Module                        | Input → Output                                      |
|------+-------------------------------+-----------------------------------------------------|
|    1 | ~Lisp.Lexer~                  | source text → ~[Token]~                             |
|    2 | ~Error.Linter~                | ~[Token]~ → warnings (does not stop compilation)    |
|    3 | ~Lisp.Parser~                 | ~[Token]~ → ~Module~ of =defn= and =graph= ~S.Expr~ |
|  3.0 | ~Error.Linter~                | ~Module~ → warnings (does not stop compilation)     |
|  3.1 | ~Lisp.Canon~                  | ~S.Expr~ → placeholders, then desugared ~S.Expr~    |
|  3.2 | ~Data.Ouro~                   | select the target graph (with a "did you mean")     |
|    4 | ~Lisp.Eval.Engine~            | ~S.Expr~ → ~(L.Expr, [OuroError])~                  |
|    5 | ~Data.Ouro.validateAST~       | the verification gate                               |
|    6 | ~Lisp.Eval.Types.freeze~      | ~L.Expr~ → ~I.Expr 'Primitive~                      |
|    7 | ~Json.Serializer.toJSON~      | ~I.Expr~ → JSON text                                |

Errors from passes 1 and 3 stop compilation immediately (there is no tree to continue with).
From pass 4 onwards, errors are collected and reported together.

* The Language (Syntax Layer)
** Program structure

An Ouro file (a module) is a sequence of top-level declarations, in any order:

#+BEGIN_SRC clojure
(defn name (arg ...) expr)   ; a named function, visible throughout the file
(graph name expr)            ; a JSON-LD graph, compiled with -t name
#+END_SRC

Every body is exactly one expression: a function's body is its result, and a graph's body is its document (usually a record). Private values are bound around that expression with =let=. A function's header can also declare its types (see [[*Functions: =defn=, =fn= and calls][signatures]]).

#+BEGIN_SRC clojure
(defn getty-aat ()
  "http://vocab.getty.edu/aat/")

(defn type-node #rec (#str aat-id label)
  (let ($prefix "Type: ")
    (:id     #uri (+ (getty-aat) aat-id)
     :type   "Type"
     :_label (+ prefix label))))

(graph spring
  (let ($artist "Manet")
    (:context       "https://linked.art/ns/v1/linked-art.json"
     :_label        (+ artist ", Spring")
     :classified_as ((type-node "300033618" "Painting")))))
#+END_SRC

Compiles (with ~ouro compile file.ouro -t spring~) to:

#+BEGIN_SRC json
{
  "@context": "https://linked.art/ns/v1/linked-art.json",
  "_label": "Manet, Spring",
  "classified_as": [
    {
      "id": "http://vocab.getty.edu/aat/300033618",
      "type": "Type",
      "_label": "Type: Painting"
    }
  ]
}
#+END_SRC

Only graphs are serialised. Functions exist to build and reuse values. A module-wide constant is written as a zero-argument function, such as =getty-aat= above.

** Lexical elements

| Element        | Written as                               | Notes                                                               |
|----------------+------------------------------------------+---------------------------------------------------------------------|
| Line comment   | =;; text=                                | from =;= to the end of the line                                     |
| Block comment  | see below the table                      | may span lines                                                      |
| String         | ="text"=                                 | Haskell-style character escapes                                     |
| Number         | =42=, =-3.5=, =1e3=                      | a Double: integers are exact up to 2^53                             |
| Boolean / null | =true=, =false=, =null=                  |                                                                     |
| Symbol         | =artist=, =type-node=, =+=, =legacy!=    | starts with a letter or an operator character (see below the table) |
| Attribute      | =:key=, =:@vocab=                        | letters, digits, =-= and =_=, after an optional =@=; a pair's key   |
| Binding        | =$name=                                  | any symbol; a private binding, only inside a =let=                  |
| Reader tag     | =#uri=, =#date=, =#str=, =#num=, =#bool= | asserts the type of what follows; also =#rec=, =#arr=, =#fn=        |
| Empty values   | =#rec-empty=, =#arr-empty=, =()=         | ={}=, =[]= and =[]=                                                 |
| Hole           | =?=, =?name=, =?..name=                  | a placeholder in a call, or part of a pattern                       |
| Delimiters     | =( )=                                    | =[ ]= is reserved: it parses, but has no meaning yet                |
| Keywords       | =defn=, =graph=, =import=, =export=      | a keyword that only begins a longer name (=defnode=) is a symbol    |

Block comments are written ~#| … |#~. A symbol starts with a letter or one of the operator characters ~_ + - * / < > = ! & | ~~, and may also contain digits, ~?~ and ~'~.

A source file is UTF-8, on every platform. A letter is any Unicode letter, so =café= is a name and =:naïve= a key, and strings hold any text. A leading byte order mark is dropped and CRLF line endings become LF, so a file reads the same wherever it was saved; a file that is not valid UTF-8 is an error, not garbled text (~Data.Ouro.readSource~). The compiler's messages are UTF-8 too: on Windows the console's code page is switched to UTF-8 (65001) while =ouro= runs, and restored when it exits.

A trailing =!= on a function name is allowed but has no meaning. Names live in one namespace, values and functions share it, and an inner value shadows an outer function of the same name.

** Formal grammar (EBNF)

The grammar below describes the language accepted by the parser and evaluator together. Several productions share the same parenthesised notation; [[*Structural classification][structural classification]] decides which one a form is.

#+BEGIN_SRC ebnf
(* ---------- Modules ---------- *)
module       = { declaration } ;
declaration  = defn | graph ;
defn         = "(" , "defn" , symbol , [ tag ] , params , expression , ")" ;
graph        = "(" , "graph" , symbol , expression , ")" ;
params       = "(" , { [ tag ] , ( symbol | param-pattern ) } , ")" ;     (* a tag types the parameter after it *)
param-pattern = record-pattern | array-pattern ;     (* binds the parts of one argument *)

(* ---------- Expressions ---------- *)
expression   = literal | tagged | symbol | record | array | call | special-form ;

literal      = string | number | "true" | "false" | "null"
             | "#rec-empty" | "#arr-empty" | "(" , ")" ;
tagged       = tag , expression ;
tag          = "#uri" | "#date" | "#str" | "#num" | "#bool" | "#rec" | "#arr" | "#fn" ;

(* A record: at least one attribute pair or context *)
record       = "(" , { record-item } , ")" ;
record-item  = attribute-pair | context | inlay ;
attribute-pair = attribute , expression ;
attribute    = ":" , [ "@" ] , key ;     (* "@" makes a JSON-LD keyword, :@id *)

(* An array: a form whose first element is not a symbol, or an explicit list *)
array        = "(" , [ non-symbol-expr , { expression } ] , ")"
             | "(" , "list" , { expression } , ")" ;

(* A call: a form headed by an expression that evaluates to a function *)
call         = "(" , symbol , { expression | placeholder } , ")" ;
placeholder  = [ tag ] , hole ;     (* a call with placeholders is a function of them *)

(* ---------- Special forms ---------- *)
special-form = let | fn | case | get | nth | map | insert | replace-at | attr | with | thread ;
let          = "(" , "let" , "(" , { binding } , ")" , expression , ")" ;
binding      = "$" , symbol , expression ;
fn           = "(" , "fn" , [ tag ] , params , expression , ")" ;
case         = "(" , "case" , expression , { branch } , "(" , "otherwise" , expression , ")" , ")" ;
branch       = "(" , ( pattern | guard | alternatives ) , expression , ")" ;
guard        = "(" , comparison , expression , ")" ;
alternatives = "(" , literal , { literal } , ")" ;
get          = "(" , "get" , expression , symbol , { symbol } , ")" ;
nth          = "(" , "nth" , expression , expression , ")" ;
map          = "(" , "map" , expression , expression , ")" ;     (* a function, then an array *)
with         = "(" , "with" , expression , { record-item | expression } , ")" ;
thread       = "(" , "->" , ( expression | placeholder ) , { expression } , ")" ;     (* a value, then its steps *)
insert       = "(" , "insert" , expression , ( expression | attribute-pair ) , expression , ")" ;
replace-at   = "(" , "replace-at" , expression , ( expression | attribute-pair ) , expression , ")" ;
attr         = "(" , "attr" , expression , expression , ")" ;     (* a computed key *)
inlay        = "(" , "inlay" , expression , ")" ;
context      = ( ":context" | ":@context" ) , expression ;     (* a JSON-LD context value *)

(* ---------- Patterns (inside case, and as parameters) ---------- *)
pattern      = hole | record-pattern | array-pattern ;
hole         = "?" | "?" , name ;
rest-hole    = "?.." , name ;
record-pattern = "(" , { attribute , sub-pattern } , [ rest-hole ] , ")" ;
array-pattern  = "(" , { sub-pattern } , [ rest-hole ] , ")" ;  (* contains at least one hole *)
sub-pattern  = hole | record-pattern | array-pattern | expression ;
#+END_SRC

** Values

| Value    | Written as                                     | JSON    |
|----------+------------------------------------------------+---------|
| String   | ="Manet"=, =#str expr=                         | string  |
| Number   | =3000=, =#num expr=                            | number  |
| Boolean  | =true=, =#bool expr=                           | boolean |
| Null     | =null=                                         | null    |
| URI      | =#uri "https://..."=                           | string  |
| Date     | =#date "1881-01-01T00:00:00Z"=                 | string  |
| Record   | =(:key value ...)=, =#rec expr=                | object  |
| Array    | =(a b c)=, =(list a b c)=, =#arr expr=         | array   |
| Duration | =(years 2)=, =(days 19)=                       | none    |
| Function | =(fn (x) ...)=, a =defn= name, =+=, =#fn expr= | none    |

Durations and functions are values during compilation, but have no JSON form: they must be consumed (added to a date, called) before they reach the output.

*Type assertions.* =#uri= checks that a string is a URI with a scheme; =#date= checks that a string is an ISO-8601 timestamp (=YYYY-MM-DDTHH:mm:ssZ=); =#str=, =#num=, =#bool=, =#rec=, =#arr= and =#fn= check the type of any expression (=#fn= accepts a =fn=, a =defn= name or a built-in). An assertion on a value that is already a URI or a Date passes it through. Assertions are how URIs and dates, which look like strings in JSON, keep their meaning inside Ouro.

** Records and arrays

A record is a form containing =:key value= attribute pairs (or a context). Its attribute pairs are output in source order, and they are also bindings: inside the record, an attribute pair's name refers to its value, in any order. Each key appears once: writing a key twice in the same record (or two contexts) is an error.

#+BEGIN_SRC clojure
(:begin_of_the_begin #date "1848-08-01T00:00:00Z"
 :end_of_the_begin   (+ begin_of_the_begin (thru (days 19))))
#+END_SRC

A form of values is an array. Because a form headed by a symbol is a call, an array whose first element is a variable is written with =list=:

#+BEGIN_SRC clojure
(1 2 3)            ; an array
(("Manet") 1)      ; an array whose first element is an array
(list artist 1)    ; an array whose first element is the value of 'artist'
(artist 1)         ; a call to 'artist' (an error if it is not a function)
#+END_SRC

An array of one record is written with nested parentheses, ~((:type "Name" ...))~, which is the usual Linked Art shape for =classified_as=, =identified_by= and similar properties. An array of one bound value is written with =list=, ~(list manet)~, since ~(manet)~ is a call.

Arrays, like JSON arrays, can hold values of any type: ~(1 "a" (:k 1) (2 3))~.

*Inlays are layers.* =inlay= splices a record's attribute pairs into the surrounding record, but a key still appears once. An attribute pair written in the record wins over an inlaid one with the same key, wherever the =inlay= is placed, and a later =inlay= wins over an earlier one:

#+BEGIN_SRC clojure
(defn base () (:type "Type" :_label "Painting"))

(:_label "Spring" (inlay (base)))   ; {"_label": "Spring", "type": "Type"}
#+END_SRC

An inlaid record's context is layered the same way, by the context's =Monoid=: the record's =@context= is the inlays' contexts, in order, then its own written context, as one context array. Because JSON-LD applies a context array in order, the written context, applied last, overrides a term an inlay's context also defines, and a later inlay's overrides an earlier one's; terms only an inlay defines stay in scope. The same context reaching a record twice in a row, as when an inlaid node and the record both name Linked Art's context, is written once.

#+BEGIN_SRC clojure
(defn c () (:context "https://a.org/c.json" :a 1))

((inlay (c)) :context "https://w.org/c.json" :b 2)
; {"@context": ["https://a.org/c.json", "https://w.org/c.json"], "a": 1, "b": 2}
#+END_SRC

** Bindings: records and =let=

There are two ways to bind a name, with a difference in serialisation:

| Form                          | Binds          | Output?                | Scope                         |
|-------------------------------+----------------+------------------------+-------------------------------|
| =(:name expr ...)= (a record) | its fields     | yes, every field       | the record's own expressions  |
| =(let ($name expr ...) body)= | its bindings   | no, only =body=        | the bindings and =body=       |

Both are recursive (=letrec=): the bindings can refer to each other in any order, and a cycle is an error. An inner binding shadows an outer one, but a binding is always evaluated in the scope where it was written:

#+BEGIN_SRC clojure
(let ($artist "Manet"
      $painted-by artist)                 ; written here, so "Manet"
  (:provenance (:artist     "Proust"
                :owner      artist        ; the inner 'artist': "Proust"
                :painted-by painted-by))) ; still "Manet"
#+END_SRC

*A binding never sees itself.* Inside its own expression, a binding's name refers to the enclosing scope, so in ~(:name name)~ the attribute pair outputs the =name= from outside the record, and in ~(let ($x (+ x 1)) x)~ the =x= being added to is the outer one. This is what makes templates such as ~(defn node (id type) (:id id :type type))~ work. A name with nothing outside is unbound, and siblings that refer to each other in a cycle are still an error.

A =let= binds private values with =$name value= pairs. The =$= marks a binding that is never output, as =:= marks a key that is. A =:key= in a =let='s bindings is an error, and so is a =$name= anywhere outside them: a binding is referred to by its bare name.

** Functions: =defn=, =fn= and calls

| Form                     | Meaning                                                             |
|--------------------------+---------------------------------------------------------------------|
| =(defn name (x y) expr)= | a named function; top level only; visible throughout the file       |
| =(fn (x y) expr)=        | an anonymous function value, closed over the scope it is written in |
| =(f a b)=                | a call: =f= is any expression that evaluates to a function          |

Both kinds of function take an optional signature: =(defn name #type (#type x y) expr)=, =(fn #type (#type x) expr)=.

=λ= is another way to write =fn=: ~(λ (x) (+ x 1))~. The lexer reads =λ= on its own as =fn=, so it is =fn= everywhere, and messages name it =fn=; it cannot name a function or a binding, but a longer name that begins with it, such as =λx=, is an ordinary symbol.

A local function is a =let=-bound =fn=:

#+BEGIN_SRC clojure
(let ($attribute (fn (label) (+ label " (attributed)")))
  (:attributed (attribute (attribute "Manet"))))
#+END_SRC

*The body.* A function's body is one expression, written exactly as it would be anywhere else, and its value is the result. A body can be a =let=, so a function binds its private values the same way a graph does. Because parentheses around values make an array, ~(fn () ("hello"))~ returns ~["hello"]~; the compiler warns (=WRN0002=) when a result is a single plain value in parentheses, unless a return type of =#arr= says the array is intended.

Semantics of a call:

- *Arity* is checked: a call with the wrong number of arguments is an error. Functions are not curried.

- *Arguments are call-by-need:* each argument becomes a promise over the caller's scope. It is evaluated at most once, when the function first uses it, and always means what it meant at the call site, so a function's own bindings can never capture it. An argument the function never uses is still evaluated when the graph is finished, so its errors are reported.

- *The body is evaluated in the function's closure*, extended with a frame for the parameters. For a =defn= the closure is the module; for a =fn= it is the scope where the =fn= was written.

  A function cannot see its caller's bindings.

- *Recursion is forbidden.* Calling a function that is already being called (identified by name and definition position) is an error. Nesting a call, ~(f (f x))~, is two calls, not recursion.

- *Functions are values:* they can be passed as arguments and returned, but cannot be compared (=eq= on functions is a type error) or serialised.

- *A returned function is called through =let=.* A form headed by a call is an array, so ~((f x) y)~ does not call the result of ~(f x)~. Bind it first: ~(let ($g (f x)) (g y))~. A function can return a =fn= waiting for the remaining arguments (or a [[*Placeholders][placeholder]], ~(+ ? n)~):

  #+BEGIN_SRC clojure
  (defn adder (n) (fn (x) (+ n x)))

  (graph g
    (let ($inc (adder 1))
      (:r (inc 2))))              ; {"r": 3}
  #+END_SRC

A =defn= body is checked when the file is parsed: it must be one expression and cannot be a spliced record (~(defn f (x) :k v)~). A =define= or a nested =defn= in it is reported with its replacement, =let= or a =let=-bound =fn=.

*Signatures.* A function's types are tags in its header: a tag between the name and the parameters is the return type, and a tag before a parameter is that parameter's type. Either can be left out, and so can any parameter's.

#+BEGIN_SRC clojure
(defn node #rec (#uri id type)
  (:id id :type type))

(let ($double (fn #num (#num n) (* n 2)))
  (:r (double 21)))               ; {"r": 42}
#+END_SRC

- The types are the type tags: =#str=, =#num=, =#bool=, =#uri=, =#date=, =#rec=, =#arr= and =#fn=. There is one sigil for types: =#= always asserts a type, and its position says what it applies to.
- A signature's tag behaves exactly as the same tag would anywhere else: it checks the value, and =#uri= and =#date= convert a string. In =node= above, =id= arrives as a URI.
- Each argument is checked where the call is written, so a mismatch is reported at the argument, in the call. The result is checked where the body is, and a mismatch is reported there.
- An argument is checked even if the function never uses it.
- Nothing is inferred: an untyped parameter or result is not checked, and unannotated code behaves as before.

*Signatures are contracts.* A signature is a promise between two parties: the caller promises arguments of the parameters' types, and the function promises a result of its return type. It is checked when values cross it, as a contract is (Findler and Felleisen's higher-order contracts, as in Racket), not before evaluation, as a static type is. A failed check blames the party that broke its promise: a bad argument is reported at the call, and a bad result at the function's body. Because Ouro evaluates everything at compile time, contracts cost nothing in the output: every check has run before the document is written.

*** Placeholders

A call with =?= holes among its arguments is not called: it is a function of its holes, and the arguments it is given fill them in.

#+BEGIN_SRC clojure
(defn node (id type) (:id id :type type))

(graph g
  (let ($inc      (+ ? 1)                  ; (fn (a) (+ a 1))
        $painting (node ? "Painting")      ; (fn (a) (node a "Painting"))
        $square   (* ?n ?n))               ; (fn (n) (* n n))
    (:r (inc 41)
     :s (painting "https://a.org/1")
     :t (square 7))))                      ; {"r": 42, "s": {"id": "https://a.org/1", "type": "Painting"}, "t": 49}
#+END_SRC

- *Each =?= is a parameter*, in the order the holes are written: ~(- ? ?)~ takes two arguments, the first to subtract from.
- *A named hole is one parameter*, however often it is written: ~(* ?n ?n)~ takes one. Parameters follow the order in which each hole is first written, so ~(+ ?a ?b ?a)~ takes =a= then =b=.
- *A tagged hole is a typed parameter*: ~(node #uri ? "Painting")~ checks, and converts, its argument as a signature would, and a mismatch is reported at the argument where the placeholder is called. An untyped hole passed to a typed parameter of the function is checked by that function, and a mismatch is reported at the hole.
- *A hole belongs to the call it is an argument of*, so ~(* 2 (+ ? 1))~ multiplies 2 by a function (an error), and ~(f (g ?))~ passes =f= a function.
- *Any call takes holes*: a =defn=, a =fn=, a built-in, a variadic operator (~(< ? 10 20)~) and the special forms that evaluate their arguments (=get=, =nth=, =insert=, =replace-at=, =list=, =map=, =->=). The forms with their own structure (=let=, =fn=, =case=, =attr=, =context=, =inlay=, =thru=) do not.
- *A placeholder is a value*: it is a =fn=, closed over the scope it is written in, so it can be bound, passed and returned like one. It is called with exactly as many arguments as it has holes.
- *A hole anywhere else is an error*: in an array, in a record, or as a binding's value. A rest hole, =?..name=, only matches the rest of an array or record, so it can only be written in a pattern: a =case= pattern or a [[*Destructuring parameters][parameter]].

The holes in a =case= pattern are not placeholders: they match values (see [[*=case= and patterns][patterns]]). A placeholder can be written in a branch's body.

*** Destructuring parameters

A parameter can be a pattern, written as a =case= pattern is. It takes one argument and names its parts:

#+BEGIN_SRC clojure
(defn label-of ((:_label ?l)) l)

(graph g
  (:people (map (fn ((?slug ?label)) (:id slug :_label label))
                (("allan" "Scott Allan") ("beeny" "Emily Beeny")))
   :label  (label-of (:type "Type" :_label "Beauty"))))
; {"people": [{"id": "allan", "_label": "Scott Allan"}, {"id": "beeny", "_label": "Emily Beeny"}],
;  "label": "Beauty"}
#+END_SRC

- *A pattern is one parameter*: ~(fn ((?a ?b)) ...)~ takes one argument. Names and patterns can be mixed: ~(defn sum (base (?a ?b)) ...)~.
- *Any pattern* can be written: array patterns, record patterns (open, as in =case=), =?..rest= holes, and values compared by value, as in ~(fn (("Person" ?l)) l)~. A pattern must bind something, so it is a record pattern or holds a hole.
- *It is matched when the function is called*, even if the body uses none of its holes, as a typed argument is checked. The holes are bound in a frame around the body.
- *A mismatch is the caller's*: it is reported at the argument in the call, or at the array in =map=.
- *A tag before a pattern* checks the argument first: ~(fn (#arr (?a ?b)) ...)~.
- *Each name is bound once*: two parameters, two holes, or a hole and a parameter with the same name are an error, reported where the function is defined.
- *A pattern's values are evaluated where the function is defined*: a =defn='s pattern sees the module's functions, and a =fn='s sees the scope it is written in, but neither sees the function's other parameters. A check against another parameter is written in the body, with =case=.
- *Placeholders leave parameters alone*: a =fn='s parameter list is not read as calls, so a hole in it is always a pattern's.

** Special forms

Special forms are recognised by their head symbol before any name lookup, so they cannot be shadowed or used as function names.

| Form                                     | Meaning                                                                               |
|------------------------------------------+---------------------------------------------------------------------------------------|
| =(let ($n e ...) body)=                  | private recursive bindings around one expression                                      |
| =(fn (args) body)=                       | an anonymous function, optionally with a signature                                    |
| =(case target branch ... (otherwise e))= | pattern matching and guards; =otherwise= is required and last                         |
| =(get record key ...)=                   | the value at a path of keys through evaluated records                                 |
| =(nth i coll)=                           | the i-th element of an array, or the value of a record's i-th attribute pair          |
| =(map f array)=                          | an array of =f= called on each element                                                |
| =(insert i x coll)=                      | insert =x= at index =i= (an array element, or a =:key value= attribute pair)          |
| =(replace-at i x coll)=                  | replace the element or attribute pair at index =i=                                    |
| =(inlay expr)=                           | splice a record's attribute pairs into a record, or an array's elements into an array |
| =(with base item ...)=                   | =base= with =item=s written over it, as ~((inlay base) item ...)~                     |
| =(-> x step ...)=                        | =x= threaded through the steps, each receiving the value before it                    |
| =(list e ...)=                           | an array, whatever its first element is                                               |
| =(thru duration)=                        | extend a duration to the end of its unit (see Built-ins)                              |
| =(attr key-expr value)=                  | an attribute pair with a computed key (used with =insert=)                            |
| =:context e=                             | the record's JSON-LD =@context=, a context value (see [[*=@context=][=@context=]])                |

Negative indexes count from the end in =nth=, =insert= and =replace-at=. =insert= puts any value into an array, but not a =:key value= attribute pair. Neither =insert= nor =replace-at= can give a record a key it already has: that is an error, and =replace-at= may keep the replaced attribute pair's own key.

*Value-based =get=.* =get= evaluates its target and walks the resulting records, so it works through function results, =inlay=, =case= and =let= alike. Only a record's attribute pairs can be reached, =let= bindings are private. Path components are bare symbols (=(get p q r)=, not =(get p :q)=) arrays are indexed with =nth=.

*=map=.* ~(map f array)~ evaluates =f=, which must be a function (a =fn=, a =defn= name, a built-in or a placeholder), and =array=, which must be an array (=()= and =#arr-empty= are empty arrays). The result is an array of =f= called on each element, in order. Each element is passed as an ordinary call, made in a frame that binds the function and the element to names that cannot be written in Ouro, so arity, signatures and the recursion check apply as they do to any call: =f= must take one argument, a typed parameter checks every element, and a mismatch is reported at the array, since an element has no position of its own. With placeholders, ~(map (+ ? 1) xs)~ needs no =fn=, and ~(map f ?)~ is a function waiting for the array. Elements that are themselves arrays or records are taken apart by a [[*Destructuring parameters][pattern parameter]]: ~(map (fn ((?k ?v)) ...) pairs)~. =map= is a special form only at the head of a form: it cannot name a =defn=, but =:map= and =$map= are ordinary names.

*=with= and =->=.* ~(with base item ...)~ is =base= with =item=s written over it, layered as an =inlay= is: a written attribute pair wins over the base's own, and an array base has its elements spliced, so ~(with (1 2) 3 4)~ is ~(1 2 3 4)~. With nothing to add, ~(with base)~ is =base=. ~(-> x step ...)~ threads =x= through its steps, each receiving the value before it:

#+BEGIN_SRC clojure
(-> (base) (with :type "Mine") (with :_label "L"))   ; (with (with (base) :type "Mine") :_label "L")
(-> 1 (- 10))                                       ; (- 1 10): the value goes first
(-> 1 (- 10 ?))                                     ; (- 10 1): or where a hole marks it
(-> 1 wrap)                                         ; (wrap 1): a bare name is called with it
(-> 5 (case ((> 3) "big") (otherwise "small")))    ; special forms are steps too
#+END_SRC

- *A step* is called with the value as its first argument; a bare name is called with the value; a step that is a function, such as a placeholder ~(- 10 ?)~ or a =fn=, is called with the value. A step receives exactly one value, so ~(+ ? ?)~ is an arity error, and a step that is not a function is a type error.
- *=(-> ? step ...)=* is a function of the value, by the placeholder rule: ~(map (-> ? (with :seen true)) records)~.
- ~(-> x)~ is =x=. =with= and =->= are rewritten before evaluation (see [[*Desugaring (~Canon~)][desugaring]]), so they cannot name a =defn=.

** =case= and patterns

#+BEGIN_SRC clojure
(case target
  (("Manet" "Proust") "person")   ; alternatives: equal to any of the literals
  ((> 100)            "large")    ; a guard: (op args...) with target as first argument
  ((?head ?..rest)    rest)       ; an array pattern
  ((:type "Person" :_label ?l) l) ; a record pattern
  (otherwise          "other"))
#+END_SRC

The target is evaluated once; the branches are tried in order and the first match is evaluated.
A branch head is:

- =otherwise=: always matches; it is required, and must be the last branch.

- *A guard*, a form headed by a comparison (~>~, ~>=~, ~<~, ~<=~, =eq=, =neq=): the target is inserted as the comparison's first argument.

- *A pattern*, a record form or a form containing a =?= hole (described below).

- *Alternatives*, a form of literals: sugar for one branch per literal.

- *A literal*: compared with =eq=.

Patterns match /values/, written in Ouro's own construction syntax:

- *Record patterns*, =(:key pattern ... ?..rest)=, match by key in any order. They are open, extra attribute pairs are allowed, and =?..rest= binds them as a record.

- *Array patterns*, =(pattern ... ?..rest)=, match by position; =?..rest= must come last and binds the remaining elements as an array.

- *Holes:* =?= matches anything; =?name= binds the value.

- *Anything else* (literals, symbols, calls) is evaluated and compared by value, so   ~((+ 2 4) ?x)~ and ~(6 ?x)~ are the same pattern.

Pattern variables are bound in a frame around the branch body. A record written in the body
shadows them with its own attribute pairs.

** Built-ins

| Group       | Names                                     | Notes                                                                                   |
|-------------+-------------------------------------------+-----------------------------------------------------------------------------------------|
| Arithmetic  | ~+~ ~-~ ~*~ ~/~                           | variadic, left-associative; =+= also joins strings and arrays, adds durations to dates  |
| Comparison  | ~eq~ ~neq~ ~>~ ~>=~ ~<~ ~<=~              | variadic comparisons are chained: ~(< a b c)~ = a<b and b<c                             |
| Length      | ~len~                                     | ~(len x)~ is the number of an array's elements, or of a string's characters             |
| Durations   | =years months days hours minutes seconds= | ~(days 19)~ is a Duration                                                               |
| End-of-unit | =(thru d)=                                | ~(thru (days 1))~ = 1 day 23:59:59; ~(thru (years 0))~ = to the end of the current year |

An operator written with the wrong number of operands is an arity error. Ordering (~>~ ~>=~ ~<~ ~<=~) compares numbers only.

=len= takes exactly one argument. An array's elements are counted whatever their types, so ~(len (1 (2 3) (:k 4)))~ is 3, and =()= and =#arr-empty= have length 0. A string is counted in characters (Unicode code points), not bytes, so ~(len "Málaga")~ is 6. Any other value, a record or a URI included, is a type error. Recursion is banned, so a length cannot be written in Ouro itself; =len= is an ordinary built-in otherwise, so ~(map len xs)~ works.

Dates are shifted with =+= and =-=: ~(+ start (days 19))~. Shifting by months or years clips to the end of a shorter month instead of rolling over, so 31 March minus one month is the last day of February. =thru= exists for Linked Art timespans, whose
=end_of_the_end= is the last moment of a period:

#+BEGIN_SRC clojure
:begin_of_the_begin #date "1642-01-01T00:00:00Z"
:end_of_the_end     (+ begin_of_the_begin (thru (years 0)))   ; 1642-12-31T23:59:59Z
#+END_SRC

** =@context=

A record's JSON-LD context is written =:context value=. The value is an ordinary expression, and it is written as JSON-LD writes a context:

#+BEGIN_SRC clojure
(:context "https://linked.art/ns/v1/linked-art.json" ...)           ; a remote context
(:context (:@vocab "https://example.org/" :@language "en") ...)     ; a local context
(:context ("https://linked.art/ns/v1/linked-art.json"               ; several, applied in order
           (:ex        "https://example.org/ns/"
            :condition (:@id "ex:condition" :@type "@id")))
 ...)
(:context null ...)                                                 ; clears the context
#+END_SRC

- *A context is a value:* a remote context's URL (a String or a =#uri=), a local context record, =null=, or an array of them. Because it is evaluated like any other value, a function can build one: ~(defn linked-art () "https://linked.art/ns/v1/linked-art.json")~ and ~(:context ((linked-art) (:ex "https://example.org/ns/")) ...)~.
- *A local context* holds keywords and term definitions. A key starting with =@= is a JSON-LD keyword, written =:@vocab=. The context keywords are =@vocab=, =@base=, =@language=, =@direction=, =@version=, =@protected=, =@propagate= and =@import=. Any other key defines a term, which maps to an IRI (a String: an IRI, a compact IRI such as ="ex:condition"=, or another term), to =null=, or to an expanded definition, a record whose keys are =@id=, =@type=, =@container=, =@language=, =@direction=, =@reverse=, =@index=, =@nest=, =@prefix=, =@protected= or =@context=.
- *Several contexts* are written as an array and serialised as one, applied in order, as JSON-LD processes them. A context with one entry is serialised as that entry.
- *A malformed context is an error where it is written:* a remote context that is not an absolute URL, an unknown =@= keyword, a term mapped to something other than an IRI, =null= or a definition, a key in a definition that is not one of its keywords, an array inside the context's array, or a value with no place in JSON, such as a Date. Each is a "Malformed Context" error at the context's expression.
- *=:@context=* is JSON-LD's own name for the key, and means the same as =:context=. Any other key may also start with =@=, so =:@id= and =:@type= can be written in a record.
- A record has one context: writing it twice is an error. A record can hold only a context, ~(:context "https://...")~.

** Surface representation (~S.Expr~)

The parser produces an untyped tree, ~S.Expr~, that mirrors the source. Every node carries its ~SourcePos~, so every later error can point at the exact place in the file.

#+BEGIN_SRC haskell
-- In src/Data/Ouro/Lisp/Surface.hs
data Expr
    = Symbol      SourcePos Text            -- names, functions and special-form heads
    | DefunSymbol SourcePos Text            -- function identifiers (unused by the parser)
    | Literal     SourcePos LiteralValue    -- String, Number, Boolean, Null, empty Array/Record
    | Tagged      SourcePos ReaderTag Expr  -- #uri "...", #date "...", #rec (...)
    | Hole        SourcePos Text            -- ?, ?name or ?..name: a placeholder, or in a case pattern
    | Form        SourcePos [Expr]          -- (...)
    | Bracket     SourcePos [Expr]          -- [...], reserved

-- A function's parameter, the type tag written before it, if any, and the pattern it
-- destructures its argument with, if any
data Param = Param
    { paramName    :: Text
    , paramType    :: Maybe (SourcePos, ReaderTag)
    , paramPattern :: Maybe Expr
    }
#+END_SRC

A pattern parameter is named by its position, =%arg1=, =%arg2=, ..., which cannot be written in Ouro, so its argument is only reached through the pattern's holes. ~Function.checkParams~ checks the parameters when a function is defined, by the parser for a =defn= and by the evaluator for a =fn=: each pattern must bind something, and each name is bound once.

There is no separate constructor for attribute pairs: the parser reads =:key value= as the form ~(attr "key" value)~, so a record is a ~Form~ of ~attr~ forms. A =$name= is read on its own as ~(%binder "name")~ and paired with its value only inside a =let= (see [[*Desugaring (~Canon~)][desugaring]]). A module is the parser's other output: a registry of =defn= declarations and a registry of =graph= declarations, each a ~HigherExpression~ indexed by its kind:

#+BEGIN_SRC haskell
data HigherExpression (t :: Declaration) where
    Function :: SourcePos -> Text -> [Param] -> Expr -> HigherExpression 'FunctionExpr
    Graph    :: SourcePos -> Text -> Expr            -> HigherExpression 'GraphExpr
#+END_SRC

A =defn='s return type is applied when it is parsed: its body is stored under the return tag, as ~Tagged~. A =fn= is an ordinary form until it is evaluated, where a return tag is read from its parameter list, ~(fn #num (n) ...)~.

The parser also enforces the module-level rules: a function name cannot be a special form, a function cannot be defined twice, a body must be one expression, and the removed keywords (=defun=, =define=, a nested =defn=) are reported with their replacements.

** Desugaring (~Canon~)

Before evaluation, ~Canon.canonicalModule~ rewrites every function body and graph into a smaller core by running ~Canon.passes~ in order, one rule per pass. Each pass relies on the ones before it:

| Pass             | Walk      | Rewrites                                                                                   |
|------------------+-----------+--------------------------------------------------------------------------------------------|
| 1. placeholders  | top-down  | a call with =?= holes into a function of them, leaving =case= and =fn= patterns as they are |
| 2. threading     | top-down  | ~(-> x step ...)~ into nested calls; a step with a hole is already a function (1)           |
| 3. bindings      | top-down  | =$name value= in a =let='s bindings into ~(%bind "name" value)~                             |
| 4. guards        | top-down  | a =case= guard ~((< 10) e)~ into ~((%guard < 10) e)~                                        |
| 5. contexts      | bottom-up | =:context e= into ~(%context e)~                                                            |
| 6. with          | bottom-up | ~(with base item ...)~ into ~((inlay base) item ...)~                                       |
| 7. thru          | siblings  | ~(thru (days n))~ into the durations it stands for                                          |
| 8. comparisons   | bottom-up | ~(< a b c)~ into ~(%and (< a b) (< b c))~                                                   |
| 9. operators     | bottom-up | ~(+ a b c)~ into ~(+ (+ a b) c)~                                                            |
| 10. alternatives | bottom-up | a =case= branch ~(("a" "b") e)~ into one branch per literal                                 |

A pass walks the tree in one of three ways (~Canon.Traverse~): top-down, rewriting a form before its parts, when the rule depends on the form's own shape; bottom-up, rewriting a form's parts first; or over lists of siblings, for a rule that turns one element into several. An expression that stands on its own, such as a graph's body or the payload of a type tag, is a list of one: a =thru= there has no meaning and is left for the evaluator to report.

The order matters in four places. Threading runs before =with=, so in ~(-> x (with :k v))~ =with= receives =x= as its base. Bindings run before =thru=, so a value that expands into several elements stays inside its binding. Guards run before comparisons and alternatives, which leave a marked guard alone, so a guard's operands are not unrolled as a comparison of their own. Only =thru= walks siblings.

Each pass is a module of its own under =Lisp/Canon/= (=Placeholders.hs=, =Threading.hs=, =Bindings.hs=, =Guards.hs=, =Context.hs=, =With.hs=, =Thru.hs=, =Comparisons.hs=, =Operators.hs=, =Alternatives.hs=, with the walks in =Traverse.hs=), and =Lisp/Canon.hs= is the single entry point: it lists the passes, in order, and runs them (~Canon.runPasses~ runs any selection of them). A =defn='s parameter patterns go through ~Canon.patternPasses~, every pass but placeholders and threading, since their holes match values.

| Sugar                                   | Core                                                          |
|-----------------------------------------+---------------------------------------------------------------|
| a placeholder ~(f ? x ?n #num ?)~       | ~(fn (%1 ?n #num %2) (f %1 x ?n %2))~                         |
| ~(-> x (f a) g)~                        | ~(g (f x a))~                                                 |
| a function step ~(-> x (h b ?))~        | ~(%apply (fn (%1) (h b %1)) x)~                               |
| ~(with base item ...)~                  | ~((inlay base) item ...)~; ~(with base)~ is ~base~            |
| =:context e=, =:@context e=             | ~(%context e)~: the record's metadata, not an attribute pair  |
| ~(+ a b c)~ (also =- * /=)              | ~(+ (+ a b) c)~                                               |
| ~(< a b c)~ (also ~eq > >= <=~)         | ~(%and (< a b) (< b c))~; =%and= cannot be written by users   |
| ~(thru (days n))~                       | ~(days n) (hours 23) (minutes 59) (seconds 59)~               |
| ~(thru (years n))~, ~(thru (months n))~ | ~(years-end n)~, ~(months-end n)~ (resolved against the date) |
| =case= alternatives ~(("a" "b") e)~     | one branch per literal                                        |
| a =case= guard ~((< 10) e)~             | ~((%guard < 10) e)~, chained with the target as first operand |
| =$name value= in a =let='s bindings     | ~(%bind "name" value)~                                        |

A =$name= with no value becomes ~(%bind "name")~ and is reported as having no value; a =$name= anywhere outside a =let='s bindings stays ~(%binder "name")~ and is reported where it is evaluated. Like =%and=, the =%= heads cannot be written by users. =%apply= exists because a form headed by a =fn= is an array, not a call: the evaluator binds the function to a name that cannot be written and calls it with the threaded value, as =map= does for each element. Nor can a placeholder's parameter names: =%1= cannot be lexed, and =?n= is read as a hole, so a placeholder never captures a name its call refers to. A hole left after ~Canon.Placeholders.placeholders~, outside a call's arguments and =case= patterns, is reported where it is evaluated.

** Structural classification

A plain form can be a record, an array or a call. ~determineBlockTarget~ decides which, from the
form's contents alone, before anything is evaluated:

#+BEGIN_SRC haskell
determineBlockTarget :: [S.Expr] -> BlockTarget
determineBlockTarget items =
    case items of
        []       -> TargetList
        (x : xs) -> case isFunctionApplication (x : xs) of
                        True  -> TargetFunctionApp
                        False -> case any isStructuralAttr items of
                                     True  -> TargetRecord
                                     False -> TargetList
    where
    isFunctionApplication = \case
        (S.Symbol _ name : _) -> not (isFunctionKeyword name || name == "define")
        _notAFunction         -> False

    isStructuralAttr = \case
        S.Form _ (S.Symbol _ "attr"     : _) -> True
        S.Form _ (S.Symbol _ "%context" : _) -> True
        _other                               -> False
#+END_SRC

- *Call*: the first element is a symbol.
- *Record*: otherwise, if any element is an attribute pair or a context.
- *Array*: everything else, including the empty form ~()~.

Only the direct elements of a form matter, never their types: ~(1 "a" (:k 1))~ is an array, because its record has its own parentheses, while ~(1 :a 2)~ is a record with a loose value, which is an error. A record made only of inlays has no written attribute pair, so it is read as an array (see [[*Appendix B: Known gaps][known gaps]]).

Special forms are matched by =evalExpr= before classification, so =let=, =case= and the others never reach it. These rules are why an array beginning with a variable needs =list=.

** Example projection

#+BEGIN_SRC clojure
:timespan (:type               "TimeSpan"
           :identified_by      ((:type    "Name"
                                 :content "40 days in August and September, 1848"))
           :begin_of_the_begin #date "1848-08-01T00:00:00Z"
           :end_of_the_begin   (+ begin_of_the_begin (thru (days 19))))
#+END_SRC

- =:timespan (...)= opens a nested record: its parentheses are the JSON object's braces.

- =:identified_by ((...))= is an array holding one record: the outer parentheses are the array, the inner ones the record.

- =#date= asserts that the string is a timestamp. The value stays a Date inside Ouro, so it can be shifted with =+=, and is written back as an ISO-8601 string.

- =end_of_the_begin= refers to its sibling =begin_of_the_begin=, a binding in the record's own frame. Order does not matter.

* Intermediate Representation and Evaluation

Evaluation turns the surface tree of the selected graph into ~L.Expr~, a value tree that may still contain errors and compile-time-only values. Its design mandates are:

1. *Lexical, lazy, shared:* bindings are promises evaluated at most once, in the scope where they were written.
2. *Value-based:* everything (=get=, patterns, comparison) works on evaluated values, never on code.
3. *Error isolation:* a failure becomes an ~EvalError~ leaf in place, and evaluation of the surrounding tree continues.

** ~L.Expr~

#+BEGIN_SRC haskell
-- In src/Data/Ouro/Lisp/Eval/Types.hs
data Expr where
    -- Frozen targets: already valid JSON-LD
    Primitive       :: I.Expr 'JLD.Primitive -> Expr

    -- Open structure: may contain errors at any depth
    Record          :: I.Expr 'JLD.Meta -> [(Text, Expr)] -> Expr
    Attr            :: Text -> Expr -> Expr          -- a computed attribute pair, from (attr k v)
    Array           :: [Expr] -> Expr

    -- Compile-time-only values: no JSON form
    Duration        :: PeriodUnit -> Int -> Expr
    PrimitiveOp     :: NativeFunction -> Expr       -- a built-in
    FunctionClosure :: Env -> FunctionId -> [S.Param] -> [S.Expr] -> Expr

    -- The universal error leaf
    EvalError       :: OuroError -> Expr

type NativeFunction = SourcePos -> [Expr] -> Reader Env Expr
#+END_SRC

Records are association lists, ~[(Text, Expr)]~, rather than maps:

1. *Source order is output order*, which keeps serialisation deterministic and the output recognisably shaped like the source.
2. *Errors stay local:* a failed attribute pair is an ~EvalError~ under its own key; its siblings are unaffected.
3. *One linear pass* collects every error in a record.

(Laziness no longer comes from the list: it comes from the promise store, below.)

** The environment model

#+BEGIN_SRC haskell
data Env = Env
    { _localScope       :: Map Text Binding     -- this frame's names
    , _parentEnv        :: Maybe Env            -- the enclosing frame
    , _functionRegistry :: FunctionRegistry     -- functions defined in this frame only
    , _callStack        :: Set FunctionId       -- the functions currently being called
    }

newtype Binding  = Promised Addr               -- every name is bound to a promise
type    Addr     = Int
type FunctionId  = (Text, SourcePos)           -- a function's name and definition position

type EvalM = ReaderT Env (State Store)          -- read the scope, thread the store
type Store = IntMap Promise

data Promise = Promise
    { _promiseEnv   :: Env                      -- the scope it was written in
    , _promiseExpr  :: S.Expr                   -- its code
    , _promiseName  :: Text
    , _promisePos   :: SourcePos
    , _promiseState :: PromiseState
    }

data PromiseState = Unforced | Forcing | Forced Expr
#+END_SRC

This is the environment model of Scheme (SICP §3.2) with call-by-need bindings, as in Launchbury's natural semantics for lazy evaluation:

- *Frames:* an ~Env~ is a chain of immutable frames. A record, a =let=, a call and a =case= branch each push one frame. The root frame holds the module's =defn= functions.

- *Promises:* every binding is a promise in the ~Store~, which is the only state in the evaluator. ~Reader~ carries the current scope downwards; ~State~ carries the store across, so a promise forced in one place is already forced everywhere else.

- *Functions:* each frame's function registry holds only the functions defined in that frame, so function lookup is lexical too.

- *Built-ins* read the environment only: ~NativeFunction~ runs in ~Reader Env~, never touching the store.

** Evaluation life-cycle
*** Allocating a frame

A record or a =let= is evaluated in two steps:

1. ~collectBindings~ (records) or ~letBindings~ (=let=) sweeps the forms for =:key value= attribute pairs (records) or =$name value= bindings (=let=) and returns their un-evaluated expressions as ~FrameEntry~ values. Removed forms (=define=, a local =defn=) are reported here.

2. ~allocFrame~ allocates one ~Unforced~ promise per entry and builds the frame that binds their names. Every promise's environment is that same frame, minus the promise's own name. This is what makes the bindings recursive, each binding sees all of its siblings in any order, while a binding never sees itself: its own name resolves in the enclosing scope.

#+BEGIN_SRC haskell
allocFrame :: (Map Text Binding -> Env) -> [FrameEntry] -> EvalM (Env, [Addr])
#+END_SRC

Only a name that the frame binds to that very promise is hidden from it. A function argument's promise closes over the caller's frame, where the same name is a different binding, so it is untouched. A record cannot bind a key twice (that is reported when it is emitted); in a =let=, a name bound twice resolves to the first binding.

*** Forcing

#+BEGIN_SRC haskell
force :: (S.Expr -> EvalM L.Expr) -> SourcePos -> Addr -> EvalM L.Expr
force evaluator refPos addr = do
    promise <- gets (IntMap.! addr)
    case promise ^. promiseState of
        Forced value -> pure value                                  -- shared
        Forcing      -> pure (cyclicLookup refPos (promise ^. promiseName))
        Unforced     -> do
                        setState Forcing
                        value <- local (const (promise ^. promiseEnv))
                                       (evaluator (promise ^. promiseExpr))
                        setState (Forced value)
                        pure value
#+END_SRC

A promise is evaluated in /its own/ environment, not the one where it is referenced: this is what makes scoping lexical. Reaching a promise that is still being forced means the binding depends on itself, which becomes a cycle error instead of an infinite loop.

*** Looking up a name

~lookupVar~ walks outward from the current frame. In each frame it checks the bound names, then the functions defined in that frame, then moves to the parent. At the root it falls back to the built-ins. An unbound name is an error with a "Perhaps you meant" suggestion, ranked by edit distance.

*** Emitting a record

~emitProps~ walks the record's forms again, in source order:

- The record's context, ~(%context e)~, is evaluated like any value, read as a JSON-LD context by ~contextFromValue~, and becomes the record's metadata (~I.Context~).

- An attribute pair is forced through /its own promise/ (found by the position of its =:key=), so an attribute pair that is both output and referenced is evaluated once.

- =inlay= evaluates its expression and splices the resulting record's attribute pairs in place, as a layer: an inlaid attribute pair is dropped when the record writes the same key, or when a later =inlay= has it. Its context is combined under the record's with the metadata =Monoid=, ~inlaid <> rest~, where =rest= already holds the later inlays' contexts and the written one.

- A key written twice, or a second context, is an error at the second occurrence.

- An attribute pair's value must be serialisable (a primitive, record or array; see the ([[*3. The Verification Gate][verification gate]]), otherwise the attribute pair becomes an error.

- A loose expression that is not an attribute pair is an error ("Unbound expressions are not allowed inside =Record= blocks").

Arrays (~compileArray~) evaluate their elements in order, with =inlay= splicing arrays.

*** Calling a function

~evalFunction~ checks arity and recursion, allocates one promise per argument over the /caller's/ environment (under its parameter's tag, if the parameter is typed), and evaluates the body in the closure extended with a parameter frame:

#+BEGIN_SRC haskell
(_, argAddrs) <- allocFrame (const callerEnv) [ FrameEntry (paramName param) (exprPos arg) (typedArgument param arg) False | ... ]
let functionEnv = closureEnv
                & localScope       .~ Map.fromList (zip (map paramName params) (map Promised argAddrs))
                & functionRegistry .~ Map.empty
                & parentEnv        .~ Just closureEnv
                & callStack        .~ Set.insert fnId callerStack
#+END_SRC

Then ~destructure~ forces each pattern parameter's promise and matches it with ~matchPattern~, the matcher =case= uses. The pattern's values are evaluated in the closure, carrying this call's stack so the recursion check holds, rather than in the parameter frame. The holes of every pattern are bound, as already-evaluated values, in one frame between the parameter frame and the body; a value that does not match is reported at its argument.

*** Finishing

~evaluate~ evaluates the graph, then forces every promise that is still ~Unforced~, repeating until none are left (forcing can allocate new promises). The errors found in those values are returned alongside the graph:

#+BEGIN_SRC haskell
evaluate :: Module -> S.Expr -> (L.Expr, [OuroError])
#+END_SRC

Only error leaves count: a binding that holds a Duration or a function is fine as long as it never reaches the output. Forcing a =fn= creates its closure but does not run its body, so an error inside a function that is never called is not reported.

** Error isolation

Ouro does not short-circuit. Each failure becomes an ~EvalError~ at the position where it happened, and the evaluator carries on with the rest of the tree. Operations propagate an error argument rather than failing again, so one mistake produces one message. Errors are constructed in ~Error.Diagnostics~ and carry a code derived from their constructor (=SYN=, =TYP=, =SCP=, =INT=, and =WRN= for warnings), a message and a blurb.

* The Verification Gate

Before anything is serialised, ~validateAST~ walks the evaluated tree and collects:

1. Every ~EvalError~ in the output.

2. Every value that has no JSON form: Durations, functions, built-ins and schema values, reported at the graph's position with the key path to the value (for example ='produced_by.timespan'=).

3. Infinity and NaN, which JSON cannot represent.

4. the errors found in unused bindings, passed in from ~evaluate~.

Errors are de-duplicated (an error in a binding that is also in the output is reported once) and sorted by position. *A graph compiles if and only if this list is empty.*

There are two guards against compile-time-only values. ~emitProps~ checks each record attribute pair as it is emitted, which catches most mistakes with a precise position. ~validateAST~ then checks the whole tree, which also covers the graph root and array elements.

** Type collapse (~freeze~)

A tree that passes the gate contains only ~Primitive~, ~Record~ and ~Array~ nodes. ~freeze~ folds it into the ~I.Expr~ GADT:

#+BEGIN_SRC haskell
freeze :: Expr -> I.Expr 'JLD.Primitive
freeze = \case
    Primitive p -> p
    Record  m p -> I.Record m (foldRecordToGADT p)
    Array     p -> I.Array (foldArrayToGADT p)
    other       -> error ("Invariant: Non-serializable node type: " ++ ...)
#+END_SRC

Building a statically indexed GADT from runtime lists requires an ~unsafeCoerce~ in the bridge to ~I.Expr any~. It is justified by the gate: ~validateAST~ is the lemma that every node is one of the three serialisable shapes. The ~error~ calls in ~freeze~ are internal invariants, not user errors; reaching one means a value bypassed the gate, which is a compiler bug.

* The Internal Model (~I.Expr~)

JSON-LD is represented by a GADT indexed by a promoted kind, so that ill-formed documents cannot
be constructed:

#+BEGIN_SRC haskell
-- In src/Data/Ouro/Internal/Kinds.hs
data Type = Primitive | Context | List | Meta

-- In src/Data/Ouro/Internal/Expr.hs
data Expr (t :: JLD.Type) where
    -- Leaves
    String    :: Text    -> Expr 'JLD.Primitive
    Number    :: Double  -> Expr 'JLD.Primitive
    Boolean   :: Bool    -> Expr 'JLD.Primitive
    URI       :: URI     -> Expr 'JLD.Primitive
    Date      :: UTCTime -> Expr 'JLD.Primitive
    Null      ::            Expr 'JLD.Primitive
    BlankNode :: Text    -> Expr 'JLD.Primitive
    EmptyArr  ::            Expr 'JLD.Primitive
    EmptyRec  ::            Expr 'JLD.Primitive

    -- Metadata
    Context   :: Schema -> Expr 'JLD.Meta
    EmptyMeta ::           Expr 'JLD.Meta

    -- The list backbone
    Cons      :: Expr head -> Expr tail -> Expr 'JLD.List
    Attr      :: Text      -> Expr any  -> Expr 'JLD.List
    Nil       ::                           Expr 'JLD.List

    -- Boundary gates
    Record    :: Expr 'JLD.Meta -> Expr 'JLD.List -> Expr 'JLD.Primitive
    Array     :: Expr 'JLD.List                   -> Expr 'JLD.Primitive
#+END_SRC

| JSON-LD                 | Ouro                | ~I.Expr~ constructor    | Haskell type   | Kind      |
|-------------------------+---------------------+-------------------------+----------------+-----------|
| string                  | ="text"=            | ~String~                | ~Text~         | Primitive |
| number                  | =42=                | ~Number~                | ~Double~       | Primitive |
| boolean                 | =true=              | ~Boolean~               | ~Bool~         | Primitive |
| null                    | =null=              | ~Null~                  | none           | Primitive |
| IRI                     | =#uri "..."=        | ~URI~                   | ~Text.URI.URI~ | Primitive |
| xsd:dateTime            | =#date "..."=       | ~Date~                  | ~UTCTime~      | Primitive |
| blank node              | not yet written     | ~BlankNode~             | ~Text~         | Primitive |
| ={}= / =[]=             | =#rec-empty= / =()= | ~EmptyRec~ / ~EmptyArr~ | none           | Primitive |
| node object             | =(:k v ...)=        | ~Record~                | meta + list    | Primitive |
| array                   | =(a b ...)=         | ~Array~                 | list           | Primitive |
| =@context=              | =:context ...=      | ~Context~ / ~EmptyMeta~ | ~Schema~       | Meta      |
| member / attribute pair | none                | ~Cons~, ~Attr~, ~Nil~   | none           | List      |

The indices enforce three boundaries:

- *Leaves are leaves:* primitives are indexed ~'Primitive~ and cannot appear where a list spine is expected.

- *The spine is isolated:* ~Cons~, ~Attr~ and ~Nil~ are indexed ~'List~, so collection mechanics never leak into a leaf position.

- *Metadata has one slot:* the first argument of ~Record~ is the only place a ~'Meta~ value can go, so a context can never be written as an ordinary value.

~Record~ and ~Array~ are the gates that lift a spine back to a ~'Primitive~ value. (The ~Context~ kind is currently unused.)

The context model (~Internal.Schema~) is a context's entries, in order:

#+BEGIN_SRC haskell
newtype Schema = Schema [ContextEntry]        -- Monoid: concatenation, mempty = []

data ContextEntry
    = RemoteContext URI                        -- "https://..."
    | LocalContext  Directives                 -- {...}
    | ClearContext                             -- null

newtype Directives = Directives [(Text, ContextValue)]   -- Monoid: right-biased union

data ContextValue = CString Text | CNumber Double | CBool Bool | CNull
                  | CArray [ContextValue] | CObject [(Text, ContextValue)]
#+END_SRC

- *Contexts are a Monoid under concatenation.* JSON-LD processes a context array in order, each entry against the context the earlier ones built, so concatenation is how contexts compose; it is associative, and the empty context, which changes nothing, is the identity. Adjacent local contexts are kept apart, not merged, so each keeps its meaning. Applying the same entry twice in a row is applying it once, so where two contexts meet an entry equal to the one before it is dropped: ~[X] <> [X]~ is ~[X]~. Only neighbours collapse: in ~[X, Y, X]~ the second =X= is applied against what =Y= built, so it is kept. The laws hold for contexts built with =<>=, which never hold two equal neighbours.
- *Local contexts are a Monoid under a right-biased union.* A key in both keeps the position of its first occurrence and the value of its later one, as defining a term again replaces it; the empty local context is the identity. A local context is built with ~directive key value~ and ~<>~, so each key appears once.
- *A record's metadata is a Monoid too*, over ~I.Expr 'Meta~: two =Context=s combine as their =Schema=s do, and =EmptyMeta= is the identity. =inlay= uses it to layer an inlaid record's context under the record's own.
- ~Eval.Schema.contextFromValue~ reads an evaluated value as a ~Schema~ and checks it; ~Json.Parser~ reads a JSON =@context= the same way for =ouro validate=, keeping a context array's structure. The serialiser writes a ~Schema~ with one entry as that entry, and one with several as an array.

* The Emission Engine

Serialisation (~Json.Serializer.toJSON~) is a catamorphism over ~I.Expr~: one recursive descent, ~buildJSON~, that emits each node exactly once, in order.

#+BEGIN_SRC haskell
newtype Printer a = Printer
    { runPrinterP :: ReaderT PrinterEnv (StateT PrinterState Identity) a }

data PrinterEnv   = PrinterEnv   { options :: !PrinterOptions, nestingLevel :: !Int }
data PrinterState = PrinterState { activeDirectives :: ![ContextEntry]
                                 , outputBuffer     :: !Builder }
#+END_SRC

- *Reader for layout:* the nesting level flows downwards with ~local~, so entering a structure indents its children without affecting its siblings.

- *State as an append-only buffer:* serialisation is monotonic: output is only ever appended, never rewound. A ~Text.Lazy.Builder~ accumulates it without repeated string concatenation.

- *Strict fields:* the bang patterns on ~PrinterState~ prevent a chain of unevaluated thunks from building up across a deep traversal (the classic lazy-state space leak).

- *Identity at the base:* the stack has no ~IO~. The printer is a pure function from a frozen tree to text; nothing is "run" in a virtual machine.

The output is UTF-8 with LF line endings and a trailing newline. Numbers that are whole print without a decimal point.

The same serialiser backs ~ouro validate~, which parses JSON-LD into ~I.Expr~ (~Json.Parser~) and prints it back, as a check that a document is representable.

* Architectural Boundaries
** Module layering

Dependencies flow in one direction, from the pure JSON-LD core upwards:

| Layer        | Modules                                                                                                          | May import                                                   |
|--------------+------------------------------------------------------------------------------------------------------------------+--------------------------------------------------------------|
| JSON-LD core | ~Internal.Kinds~, ~Internal.Schema~, ~Internal.Expr~, ~Internal.Utils~                                           | each other only                                              |
| JSON I/O     | ~Json.Parser~, ~Json.Serializer~                                                                                 | the core                                                     |
| Errors       | ~Error.Types~ ← ~Error.Diagnostics~, ~Error.Linter~                                                              | the core, ~Lisp.Tokens~, ~Lisp.Surface~, ~Lisp.Module.Types~ |
| Front end    | ~Lisp.Tokens~, ~Lisp.Lexer~, ~Lisp.Surface~, ~Lisp.Function~, ~Lisp.Parser~, ~Lisp.Canon~ (and its passes), ~Lisp.Module.Types~ | errors, each other                                           |
| Evaluator    | ~Eval.Types~ ← ~Eval.Builtins~, ~Eval.Schema~, ~Eval.Pattern~ ← ~Eval.Scope~ ← ~Eval.Structural~ ← ~Eval.Engine~ | everything below                                             |
| Pipeline     | ~Data.Ouro~                                                                                                      | everything                                                   |
| Command line | =app/= (~CLI.Parser~, ~CLI.Runner~, ~CLI.Printer~)                                                               | ~Data.Ouro~ only                                             |

Invariants:

- The JSON-LD core never imports the evaluator: ~I.Expr~ knows nothing about Ouro.

- The front end never evaluates: parsing, rule checks and desugaring work on ~S.Expr~ alone.

- Built-ins and the schema parser only read the environment (~Reader Env~); only ~Scope~, ~Structural~ and ~Engine~ touch the promise store.

- One exception to note: ~Error.Diagnostics~ imports ~Eval.Types~ (to describe values in messages), so the error layer is not entirely below the evaluator.

** Ouro as a structural assembler

Ouro's compiler guarantees structural validity: a compiled graph is well-formed JSON whose values have the types they were asserted to have. It does not resolve vocabularies, fetch remote contexts or check terms against CIDOC-CRM.

- *Justification:* limiting the compiler to structure keeps it deterministic, offline and immune to failures in external Linked Data services.

- *Boundary rule:* URIs and keys are accepted as literal (or computed) strings. Semantic expansion (context resolution, RDF conversion, shape validation) is left to specialised tools after compilation, in keeping with the Unix philosophy.

Why quoting went: curators compose and restructure records; they do not manipulate code. Without quoting, code and values cannot be confused, which is what makes the language referentially transparent.

* Appendix B: Known gaps

Recorded 2026-10-12 and kept up to date since; none were caused by the scoping redesign. Each open gap is pinned in =Language.knownGaps= (=test/Ouro/LanguageTest.hs=) by its current, incorrect behaviour, in a test named "gap N: …"; the change that fixes a gap flips its test.

1. /Fixed:/ =@context= handling was incomplete: only four directives could be written, with no term definitions or =null=, and a remote context with local directives serialised as a nested =@context= object, which is invalid JSON-LD. A context is now a value written as JSON-LD writes it, and several contexts are an array (see [[*=@context=][=@context=]]).

2. /Fixed:/ variadic operators under a type tag hit an internal error. A tag's payload is now desugared like any other expression.

3. /Fixed:/ guards with more than one operand hit the same internal error. A guard now chains with the target as its first operand, and an operator written with the wrong number of operands is an arity error rather than an internal one.

4. /Fixed:/ month and year arithmetic rolled over into the next month (31 March − 1 month was 2 March). It now clips to the end of the shorter month.

5. *Computed keys are dropped inside records:* ~((attr k 1))~ produces ={}=. They only work via =insert=.

6. /Fixed:/ duplicate keys were emitted twice. Each key now appears once (see [[*Records and arrays][Records and arrays]]).

7. /Fixed:/ ~(:name name)~ was a self-reference (a cycle). A binding now never sees itself, so the name refers outward.

8. /Fixed:/ source was read in the Windows code page, so accented names were garbled, and so were the compiler's diagnostics. Source is now read as UTF-8 on every platform, and messages are written as UTF-8 (see [[*Lexical elements][Lexical elements]]).

9. *Suggestions miss local names:* "Perhaps you meant" ranks only the root scope.

10. *Stale wording in messages:* the hint for a function used as a value suggests =(name! args)=; =get='s missing-key blurb mentions =define=; subtraction's type error names an internal type, "a Date minus a L.Duration"; a =$= binding named after a special form (=$get=) is rightly rejected, but the message calls it an attribute key ("primative" is also misspelt).

11. *A parameter named after a special form* (e.g. =fn=) gives a confusing error about =fn= syntax.

12. *Zero-argument functions re-evaluate* on every call; as pure constants they could be shared.

13. *Code health:* the =[ ]= bracket syntax parses but has no meaning; =validate= without =-o= overwrites its input; there are no tests for the CLI; and no test checks an error message as a user sees it. The ~failsWith~ checks search the Haskell =show= of an error, but the rendered diagnostic (title, code, source line and caret, blurb) is built in =app/CLI/Printer.hs=, which writes ANSI straight to stderr and cannot be imported by the tests. The planned fix: move the rendering into the library as a pure document, leaving the CLI to colour and print it, and add golden tests (=test/fixtures/errors/=, one =.ouro= and its expected =.txt= per error kind).

14. *A record made only of inlays is read as an array:* ~((inlay (a)) (inlay (b)))~ has no written attribute pair, so structural classification makes it an array, and each =inlay= then expects an array. Workaround: write at least one attribute pair.

15. /Fixed:/ empty arrays could not be joined. Arrays are no longer required to be homogeneous, so =+= on two arrays is plain concatenation.

16. /Fixed:/ =$name= written as a reference took the next expression as its value, giving misleading arity or parenthesis errors. =$name= is now read on its own and paired with its value only inside a =let=; elsewhere it is an error that says to drop the =$=.

17. *A URI's empty root path is dropped:* ~#uri "https://a.org/"~ serialises as ="https://a.org"=, which changes the IRI's text. URIs with a path (Getty's, Linked Art's) are unaffected. It comes from how the URI library renders an empty path.

18. *An attribute pair among array values has no hint:* ~(1 :a 2)~ is read as a record (one attribute pair makes the form a record), so =1= is reported as an unbound expression. The error is right, but it could suggest ~(1 (:a 2))~.

19. *Strings are not escaped in the output:* the serialiser writes a string's characters between quotes as they are, so ~"say \"hi\""~ becomes ="say "hi""=, and a backslash, newline or tab is written raw, all of which is invalid JSON. A computed key, such as ~(attr "a\"b" 1)~, is written the same way. =ouro validate= has the same fault, so a valid document with ="a\"b"= comes back as ="a"b"=.

20. *=compile -o= needs an existing directory:* compiling into an output directory that does not exist reports "Compilation Success" and then crashes with ~withFile: does not exist~, writing nothing. Not pinned by a test, since the CLI has none (gap 13).
