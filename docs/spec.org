* Design Goals

Ouro is a domain-specific language for constructing, validating and serialising CIDOC-CRM knowledge graphs.
Linked Art JSON-LD is its main target. It bridges human-readable data modelling and strict Semantic Web standards.

Any Ouro program that compiles produces well-formed JSON.

** Structural topology

Ouro code mirrors its output:
- a record ~(:key value ...)~ becomes a JSON object;
- a form of values ~(a b c)~ becomes a JSON array;
- nesting carries through unchanged.

Nothing appears in the output unless it is written as an attribute pair or an element. Everything else either:
- produces a value in place: calls, =case=, =get=, =let=;
- or disappears: =let= bindings, =define/procedure=.

The rule of thumb is /structure is written, values are computed/.
- Parentheses give the shape.
- Anything that is not an attribute pair or an element evaluates to a value where it is written.
- The one construct that changes shape is =inlay=, which splices one record or array into the surrounding one.

Ouro is still written as s-expressions, but it is no longer homoiconic in practice.
- Quoting and =eval= were removed, so programs never manipulate code as data.
- The s-expression is kept for its other property: a uniform notation whose nesting is the nesting of the data.

** Referential transparency

Ouro has no side effects, no mutable state, no quoting, and employs a recursion check to ensure termination of compilation and the generation of the JSON target.

Every expression can be replaced by its value without changing the program.
- ~((+ 2 4) 3)~ and ~(6 3)~ are the same array, match the same patterns and serialise identically.
- A property test checks this (~prop_substitution~ in =ScopingTest.hs=).

** Lexical scope, lazily

Every name means what it meant where it was written. To find what a name refers to, read outward through the enclosing parentheses, never through the call stack.

- *Order independence:* a record's attribute pairs and a =let='s bindings refer to each other in any order (This is Scheme's =letrec=). Curators can write a graph in the order that reads best.

- *Call-by-need:* every binding is a promise, evaluated at most once, only when needed, where it was written.
  - A binding is a record's attribute pair, a =let= binding or a function's argument.
  - 40 bindings that each use the previous one twice compile instantly (~prop_sharedChain~ in =ScopingTest.hs=).

- *Cycles are errors:* a binding that depends on itself is reported ("…references itself…"), never run forever.

- *No hidden errors:* once the output is built, every promise it never needed is forced. So an error in an unused binding is still reported.

- *Names are checked as written:* before anything is evaluated, the static analysis resolves every name by these rules. It covers every function and graph, of the module and of every module it imports.
  - An unbound name is reported even in a function no graph calls, or a =case= branch not taken.
  - Its "Perhaps you meant" is ranked over every name in scope there, local bindings included.
  - A path's keys, as in ~(get r part)~, are keys, not names.

** No runtime

Ouro is a compiler, not an interpreter for a program that runs later. All names, calls and patterns are resolved at compile time; the result is a static JSON-LD document. There is no virtual machine, no I/O and no network access during compilation.

- See [[*6. Architectural Boundaries][Architectural Boundaries]].

** Dynamic code, static output

Ouro is dynamically typed, with optional type refinements that are checked when values cross them. Its output is statically typed: everything is evaluated at compile time. So every document passes the verification gate before a byte is written.

Evaluation happens in a flexible, dynamically typed sandbox (~L.Expr~), in which errors are values. Before anything is serialised, the evaluated tree must pass the verification gate, It is then collapsed into ~I.Expr~, a GADT indexed by JSON-LD kinds.

- Ouro is dynamic where curators write code, and static where the output is produced.

Signatures are described under [[*Functions: =define/procedure=, =fn= and calls][functions]]. They are checked when values reach them, not as static types are. No annotation is checked before evaluation and an annotation on code that is never evaluated is never checked.

Only names, and the arity of a call of a known function, are checked before evaluation.

- See [[*Lexical scope, lazily][lexical scope]].

When a check fails, the blame falls where it belongs.
  - A bad argument is reported at the call.
  - A bad result is reported at the function's body.

This is not gradual typing in the sense of Siek and Taha. There, annotated code is checked statically, and checks are inserted only at the boundary with untyped code.

** Errors for curators

Errors are part of the design, not an afterthought.
- Every surface node carries its ~SourcePos~.
- Every error is reported with its position, a short message and a blurb that suggests a fix.
- Evaluation continues past an error, so one compile reports them all.

Names are checked before evaluation, and every unbound one is reported together. A program with one is not evaluated, so its other errors are reported once its names are put right.

Removed syntax is recognised and answered with its replacement.

#+begin_example
"The (nth index array) form has been replaced by get."
#+end_example

A function written where a value belongs, or called with the wrong number of arguments, is shown with how it is called.
- It is shown by its parameters' names: "Perhaps call it: (aat id label)", "It is called (c)."
- A built-in or an anonymous =fn= has no parameter names, so it is told to be called with its arguments.
- The call uses the function's own name, not the qualifier it was reached through.
- A function found inside an array, when the output is checked, is reported at the graph with its path (='r[0]'=).
  - Its own position is gone by then.

** Deterministic serialisation

Records keep their attribute pairs in source order: association lists, not maps. The serialiser is a single fold over the frozen GADT, the same input always produces byte-identical output.

** The Ouro compilation pipeline

The flow from source to JSON is strictly linear (~Data.Ouro.compile~):

| Pass | Module                   | Input → Output                                                  |
|------+--------------------------+-----------------------------------------------------------------|
|    1 | ~Lisp.Lexer~             | source text → ~[Token]~                                         |
|    2 | ~Error.Linter~           | ~[Token]~ → warnings (does not stop compilation)                |
|    3 | ~Lisp.Parser~            | ~[Token]~ → ~Module~ of =define/procedure= and =graph= ~S.Expr~ |
|  3.0 | ~Error.Linter~           | ~Module~ → warnings (does not stop compilation)                 |
|  3.1 | ~Lisp.Canon~             | ~S.Expr~ → placeholders, then desugared ~S.Expr~                |
|  3.2 | ~Lisp.Analysis~          | ~Module~ → errors: names, arity, recursion descends             |
|  3.3 | ~Data.Ouro~              | select the target graph (with a "did you mean")                 |
|    4 | ~Lisp.Eval.Engine~       | ~S.Expr~ → ~(L.Expr, [OuroError])~                              |
|    5 | ~Data.Ouro.validateAST~  | the verification gate                                           |
|    6 | ~Lisp.Eval.Types.freeze~ | ~L.Expr~ → ~I.Expr 'Primitive~                                  |
|    7 | ~Json.Serializer.toJSON~ | ~I.Expr~ → JSON text                                            |

Errors from passes 1 and 3 stop compilation immediately (there is no tree to continue with). The static analysis (3.2) runs once the modules imported are loaded, each of which is analysed too.

- Its errors are collected and reported together, and stop compilation before evaluation.

From pass 4 onwards, errors are collected and reported together.

* The Language (Syntax Layer)
** Program structure

An Ouro file, a module, is a sequence of top-level declarations:
- its imports and export first (see [[*Modules: =import= and =export=][modules]]);
- then functions and graphs, in any order.

#+BEGIN_SRC clojure
(define/procedure name (arg ...) expr)   ; a named function, visible throughout the file
(graph name expr)            ; a JSON-LD graph, compiled with -t name
#+END_SRC

Every body is exactly one expression.
- A function's body is its result.
- A graph's body is its document, usually a record.
- Private values are bound around that expression with =let=.
- A function's header can also declare its types (see [[*Functions: =define/procedure=, =fn= and calls][signatures]]).

#+BEGIN_SRC clojure
(define/constant getty-aat
  "http://vocab.getty.edu/aat/")

(define/procedure type-node #record (#string aat-id label)
  (let ($prefix "Type: ")
    (:id     #uri (+ (getty-aat) aat-id)
     :type   "Type"
     :_label (+ prefix label))))

(graph spring
  (let ($artist "Manet")
    (:context       "https://linked.art/ns/v1/linked-art.json"
     :_label        (+ artist ", Spring")
     :classified_as ((type-node "300033618" "Painting")))))
#+END_SRC

Compiles (with ~ouro compile file.ouro -t spring~) to:

#+BEGIN_SRC json
{
  "@context": "https://linked.art/ns/v1/linked-art.json",
  "_label": "Manet, Spring",
  "classified_as": [
    {
      "id": "http://vocab.getty.edu/aat/300033618",
      "type": "Type",
      "_label": "Type: Painting"
    }
  ]
}
#+END_SRC

Only graphs are serialised. Functions exist to build and reuse values. A module-wide constant is a function of no parameters, such as =getty-aat= above.

** Modules: =import= and =export=

A module uses another's functions by importing it, and offers its own by exporting them, both are written first in the file, before any =define/procedure= or =graph=. A file's dependencies, and what it offers, are the first thing read.

#+BEGIN_SRC clojure
(import std/base)                     ; base/aat, base/name, ...
(import linked-art/v1/people as la)   ; la/person
(export place named part-of)
#+END_SRC

*** Qualified names

An imported function is always written with a qualifier, =qualifier/name=.
- The qualifier is the path's last segment (=base=, =people=), or the name given after =as=.
- A module's own functions are written without one.
- Two imports with the same qualifier are an error that suggests =as=.
- A name is qualified when it has a =/= with something on each side, so =/= and =/== are not.

*** Exports

A module has one =(export f g ...)=, naming at least one of its own functions, each once.
- A module without one exports nothing.
- Only functions cross modules, never graphs or values, so modules hold no state.
- A module-wide constant is a function of no parameters.

*** Each module is its own

An imported module is lexed, parsed, linted and desugared on its own.
- It is loaded once, however often it is imported.
- It has its own root frame: its functions close over its own functions and imports, never the importer's.
- A local function with the same name as an imported one is a different function, =name= and =base/name=.

*** The bundled modules

The bundled modules ship inside the compiler, embedded from =lib/= when it is built, so they need no file on disk. =std= is a folder of eight, holding Linked Art's own patterns, one module per section of its model.

- Importing a =std/= module says its functions build Linked Art's nodes.

=aat= is a second folder: Linked Art's recommended terms. - =(import std)= is an error (=SCP0006=) that says =std= is a folder and lists its modules.

A module added to =lib/= is not noticed by an incremental build. =file-embed= tracks the files it embedded, and neither GHC nor cabal watches the folder.

- So a test checks that every file in =lib/= is bundled.
- =cabal clean= then =cabal build all= brings a stale build up to date.

**** =std=

- =std/vocab= holds the 18 terms Linked Art requires, and imports nothing.
  - Each is a function of no parameters, written as a value: =vocab/primary-name=.

- =std/base= holds the base patterns, and imports =std/vocab=.
  - They are constructors that take values and build a node.
  - They never extend a record: a record is a literal, or threaded through =with= and =adjoin=.
  - =core=, the =id=, =type= and =_label= every node with an id begins with: =(base/core id "Place" "Amsterdam")=.
  - Getty entities by number: =aat=, =tgn=, =ulan=, =language=.
  - Types classified by their meta-type: =work-type=, =style=, =shape=, =nationality=, =occupation=, =statement-kind=.
  - Embedded nodes: =name= and =identifier=, each taking its kind first, and =description=.
  - =statement=, which classifies its kind as Brief Text.

- =std/time= holds time spans, whose end is included.
  - =span=, from two dates.
  - =day=, =month= and =year=, from a date written to that precision: =(time/day "1832-01-23")=, =(time/year "1881")=.
  - =(time/month "1880-02")= runs to the month's last day, leap years included.
  - =year-range= for several years, and =day-range= for several days: =(time/day-range "1848-08-01" "1848-08-20")=.
  - =between=: an uncertain span, begun within one span and ended within another.
    - =(time/between (time/span a b) (time/span c d))= sets all four of a TimeSpan's ends.
  - An event is written as a literal: =(:type "Birth" :timespan (time/day "1832-01-23"))=.
    - Linked Art's events share their properties, so a constructor per event would add nothing.

- The rest follow Linked Art's sections.
  - =std/object=:
    - dimensions, =(object/height 379.5 object/centimeters)=, with =width=, =depth=, =weight=;
    - any other kind through =dimension=, its recommended units, and those Linked Art's examples use: =day-unit=, =pixels=, =kilobytes=;
    - =material=, dimension and material statements, and =part-type=.
  - =std/actor=:
    - the parts of a name, =given-name=, =middle-name=, =family-name=, and =gender=;
    - =active=, a professional life over a span;
    - contact points: =street-address=, =telephone=, =email=.
  - =std/provenance=:
    - =purchase=, which gives the Acquisition and the Payment their opposite roles;
      - title goes from the seller to the buyer, and money from the buyer to the seller;
    - =acquisition= and =payment= on their own, and =money= with its recommended currencies.
  - =std/exhibition=: =exhibiting=, =concept= and =set=.
    - They are linked by the record's own =used_specific_object=, =influenced_by= and =member_of=.
  - =std/digital=: =picture=, an image for =representation=, and =web-page=, for =subject_of=.
    - =image= is a special form, so the image is =picture=.

- A place's geometry, =defined_by=, is a WKT string written as it is.

It has one module per section of Linked Art's list, sixteen, and one each for the activity, price, role, visual, right, provenance and part types, the styles, the genders and the techniques its examples use:

18. =price-type=

- Each term is a constant, built with =std='s constructor for its kind, so =aat= imports =std=, never the reverse:

  | Kind                                | Built with                                           |
  |-------------------------------------+------------------------------------------------------|
  | a Type                              | =base/aat=                                           |
  | an object type                      | =base/work-type=                                     |
  | a statement type                    | =base/statement-kind=                                |
  | a language                          | =base/language=                                      |
  | a unit                              | =object/unit=                                        |
  | a material                          | =object/material=                                    |
  | a currency                          | =provenance/currency=                                |
  | a nationality, occupation or shape  | =base/nationality=, =base/occupation=, =base/shape=  |
  | a style                             | =base/style=                                         |
  | a gender                            | =actor/gender=                                       |

- The qualifier says the kind, so a language and a nationality share a name: =language/dutch=, =nationality/dutch=.

- A term is named from Linked Art's name, a trailing parenthesis dropped: =partsUnit= is =parts=, =Museum (as Place)= is =place-type/museum=, =Auction House (place)= is =place-type/auction-house=.

- It is labelled with Linked Art's description, as the list writes it: =US Dollars=, =(Music) Composer=, and the materials and units lower-case, =oil=, =centimeters=, as the list and its examples write them.
  - A Type keeps Linked Art's name as its label, and its description as its documentation.

- Seven are renamed.
  - The six time units are =year-unit=, =month-unit=, =day-unit=, =hour-unit=, =minute-unit= and =second-unit=.
    - =years= and its kin are built-ins.
  - Map is =map-object=, since =map= is a special form.

- Units and currencies are in =std/object= and =std/provenance= too, with lower-case unit labels there.

- =aat/language/iso= and =aat/currency/iso= are variants of =aat/language= and =aat/currency=: each term with its ISO code as its notation, as Linked Art's examples mostly write a language or a currency.
  - =(import aat/language/iso)= gives =iso/english=, =aat/language='s =english= with =:notation "en"=. The codes are ISO 639-1's two letters; Ancient Greek has none, so it has ISO 639-3's =grc=.
  - =aat/currency/iso='s codes are ISO 4217's: =us-dollars= is written =USD=.
  - Both are qualified =iso=, so a module using both imports one under another name: =(import aat/currency/iso as currency-iso)=.

- The modules are generated by =scripts/aat/generate.pl= from =scripts/aat/recommended.tsv= and =scripts/aat/examples.tsv=.
  - The first table is what =scripts/aat/extract.pl= takes from Linked Art's page.
  - The second is written by hand, in the same form: the terms Linked Art's examples use that its list does not recommend, added as the examples are written in Ouro. Each says so in its documentation.
  - A term always has the list's label, even where an example labels it otherwise, as Country, which two examples call Nation. Ouro's fixtures of the examples are changed to the list's label, or, for a term off the list that the examples label two ways, to the module's: each change is a line of =scripts/fixtures/labels.tsv=, which =scripts/fixtures/relabel.pl= applies.
  - A test checks that every term of both tables is in the modules.

*** Resolving an import

Module paths are written with =/= on every platform. Bundled modules are embedded with the platform's separator, but named with =/= too.

An import whose first segment is =std= or =aat= is always a bundled module, whatever the project holds.

A project's =std/base.ouro= is never imported.
- A =std/= module only the project has is not found (=SCP0006=).
- =ouro build= reports a module under =:sources= whose path starts with =std= or =aat= as =BLD0009=.
- =WRN0005=, raised when a project module replaced a bundled one, is retired, and its code is not reused.

Any other module is a file of the project, or of a library vendored in it. For =ouro build=, an import whose first segment names a collection is read from that library. A collection is a folder of =vendor/=, the rest of the import's path is read from the library's source folder. Any other =(import a/b)= reads =a/b.ouro= under the source folder of the importing module's own library. For the project's own modules, that is its =:sources= (see [[*Builds: =package.ouro= and =ouro build=][Builds]]).

*** Errors

| Code      | Meaning                                                                       |
|-----------+-------------------------------------------------------------------------------|
| =SCP0006= | the module does not exist                                                     |
| =SCP0007= | a qualifier names no import                                                   |
| =SCP0008= | the module does not export the name                                           |
| =SCP0009= | modules import each other in a circle                                         |
| =SCP0010= | the module's file cannot be read, such as one that is not UTF-8               |
| =SCP0011= | the host finds the module in more than one place                              |

- =SCP0006= names the files looked for and the folders of bundled modules, with the nearest bundled module's name.
  - Every missing module in a file is reported, not only the first.

- =SCP0007= suggests the import when the qualifier names a bundled module.
  - For ~(base/name "A")~ without ~(import std/base)~, it suggests the import.

- =SCP0008= lists what the module does export.

- =SCP0009= is reported at the import that closes the circle, with its path, =a → b → a=.
  - The path names only the modules on the circle.
  - Imports go one way, so a module is checked before the modules that import it.

- =SCP0011= names the files, at the import.
  - A program embedding Ouro with several roots can meet it; the command line has one source folder, so never does.

A module that cannot be loaded is reported once, however many modules import it, an error or warning inside an imported module is reported, and shown, in that module's file and line and a failed import stops the compile, so nothing after it is reported as its echo.

** Builds: =package.ouro= and =ouro build=

=ouro build [DIR] [-g module/graph ...]= builds the project in =DIR=, the current directory when it is not given.

- It is the only command that compiles Ouro: =ouro compile= was removed in 0.5.
- A project needs no file of its own.
  - Without one, its modules are the files in =DIR=, and its graphs are written to =DIR/out=.
- A =package.ouro= in =DIR= changes that. It holds one function, =package=, whose value is the project's settings:

#+BEGIN_SRC clojure
(define/constant package
  (:sources "src"
   :outputs "dist"))
#+END_SRC

*** The folder is the project

=DIR= is never looked above.
A folder that does not exist is a message, "No folder typo", not the build of a project above it.

*** One function

=package.ouro= is lexed, parsed and evaluated as a module is. Its settings are the value of =(package)=, so they are Ouro values, ~:outputs (+ "di" "st")~ included. It can import the bundled modules, and only them: any other import is =SCP0006=.

=package.ouro=  holds nothing but its function, which is a single graph /package/.
- A graph, an export or another function is =BLD0006=;

- A function named =inputs=, =build= or =exports= is =BLD0010=, the names kept for later versions;

- =package= takes no parameters (=BLD0008=);
  - Without a function named =package=, the file is =BLD0007=.
    - It names the function it found.
    - For an empty file, it suggests deleting it, since a project needs none.

- Its declarations are checked before its settings, since the settings are its function's value.

*** Settings

None is required, so ~(define/constant package #record-empty)~ is every default.

| Setting    | Type             | Meaning                                    | When not given      |
|------------+------------------+--------------------------------------------+---------------------|
| =:sources= | String           | the source folder, relative to =DIR=       | ="."=               |
| =:outputs= | String           | where the graphs are written               | ="out"=             |
| =:graphs=  | Array of Strings | the graphs built (see below)               | every graph         |
| =:ouro=    | String           | the version of Ouro the project needs      | no check            |

- A =:sources= folder that does not exist is =BLD0005=.

- =:graphs= is an Array even when it names one graph.

- =:ouro= is numbers apart by dots, as ="0.5"=.
  - A version newer than the compiler's is =BLD0015=, which names both.
  - One that is not numbers apart by dots is =BLD0016=.
  - Versions are compared number by number, a missing number being 0, so ="0.5"= is =0.5.0.0=.

- Any other setting, =:name= included, is =BLD0000=, which suggests the nearest: =:sorces= for =:sources=.

- A setting of the wrong type is =TYP0000=, saying what the setting is.

- A value that is not a record is =TYP0000= too.

- Every wrong setting is reported, at the function.
  - An evaluated record keeps no position for each attribute pair.

*** Modules

Every =.ouro= file under the source folder is a module, named by its path under it, written with =/=.

- =src/people/bob.ouro= under ="src"= is =people/bob=.

- Skipped:
  - hidden folders (=.git=, =.jj=);
  - the =:outputs= folder and the =vendor/= folder;
  - every =package.ouro=, and every folder holding one, which is a project of its own.

- Folders are compared as they are on disk, so a source folder written through =..= still skips the outputs.

- A module whose path starts with =std= or =aat=, the folders of the bundled modules, is =BLD0009=.
  - It is reported in its file, and is not built.

*** Every graph

Every graph of every module, modules nothing imports included, is written to =<outputs>/<module>/<graph>.json=.

- The graph =g= of =people/bob= is written to =out/people/bob/g.json=, its folders made.

- A module of functions only writes nothing.

- A module imported by many is loaded once, so its warnings are reported once.

- Modules are built in the order of their names.

*** The graphs chosen

=-g module/graph=, given any number of times, builds only the graphs it names, and replaces =:graphs=. Without =-g=, =:graphs= chooses them; without either, every graph of every module is built. A graph is named by its module and its name, split at the last =/=: =people/bob/g= is =g= of =people/bob=. Only the modules of the graphs chosen, and what they import, are compiled.

- So a module not chosen cannot fail the build. Only the graphs chosen are written, in the order they are named within each module.

- *Errors*:
  - a name not written =module/graph= is =BLD0018=;
  - a module the project does not build is =BLD0017=, which suggests the closest module;
  - a graph its module does not have is =SCP0004=, shown at the module's closest graph;
  - for a module with no graphs, it is =SCP0005=.

- An error in a =-g= is reported at the argument itself, =-g people/persn=.

- An error in =:graphs= is reported at the =package= function.

- =:graphs ()= builds nothing.

*** Vendored libraries

A library is used by copying it into =vendor/=, beside =package.ouro=. Every folder of =vendor/= is a /collection/, named after the folder. There is no other place for libraries.

=(import tate/people)= reads =people.ouro= from the source folder of =vendor/tate=. That is its own =package.ouro='s =:sources=, or else the folder itself. That =package.ouro= is checked as the project's is.

- A source folder that does not exist is =BLD0005=.

A library works unchanged once copied in.

- Its own imports resolve against its own source folder.

- Its =people= and the project's =people= are different modules, which never meet.

- It imports another library by the other's collection name, so its dependencies are vendored beside it.

- Its modules are compiled only when imported.
  - So its graphs are never written.
  - A module of it nothing imports never fails the build.

*Errors*:
- A collection named =std= or =aat= is =BLD0011=.
- A library with a =vendor/= of its own is =BLD0012=, since vendoring is flat.
- A collection's name that is also a top-level folder or module of a source folder is =BLD0013=.
  - The source folder is the project's or a library's.
  - It is reported when the build starts, whether or not anything imports it.
  - So =(import tate/…)= never has two meanings.
  - The project's modules under such a folder are not built, the overlap being their error.

*** Module keys and case

A module is known by its file, as spelt on disk, relative to the project's folder =src/people.ouro=, =vendor/tate/people.ouro=.

- So a file is loaded once however it is reached, and an import cycle names the files.

An import spelt in another case than its file, =(import People)= for =people.ouro=, is =BLD0014=.
- It gives the file's spelling.
- A file system that ignores case, as Windows' and macOS's do, would find it; Linux's would not.
- So a project would build on one machine and not another.
- Outside =ouro build=, such an import is not found (=SCP0006=).

*** All or nothing

If any graph of any module fails, nothing is written, and every error of every module is reported.
A stray file under the source folder, such as a scratch file, is built too, and can fail the build.

*** Retired codes

These are never raised, and their codes are not reused:
- =BLD0001=: =build.ouro='s required =:name=;
- =BLD0003=: what =build.ouro= could not hold;
- =BLD0004=: =build.ouro='s graph not named =build=.

** Lexical elements

| Element       | Written as                                     | Notes                                              |
|---------------+------------------------------------------------+----------------------------------------------------|
| Line comment  | =;; text=                                      | from =;= to the end of the line                    |
| Block comment | ~#\vert … \vert#~                              | may span lines                                     |
| String        | ="text"=                                       | Haskell-style character escapes                    |
| Number        | =42=, =-3.5=, =1e3=                            | a Double: integers are exact up to 2^53            |
| Boolean       | =true=, =false=                                | Ouro has no null (see below)                       |
| Symbol        | =artist=, =type-node=, =+=, =∧=, =legacy!=     | see below                                          |
| Attribute     | =:key=, =:@vocab=, =:crm:P2_has_type=          | a pair's key (see below)                           |
| Binding       | =$name=                                        | any symbol; a private binding, only inside a =let= |
| Property      | =#uri=, =#date=, =#string=, =#titled=          | a property of what follows (see below)             |
| Empty values  | =#record-empty=, =#array-empty=, =()=          | ={}=, =[]= and =[]=                                |
| Hole          | =?=, =?name=, =?..name=                        | a placeholder in a call, or part of a pattern      |
| Delimiters    | =( )=                                          | =[ ]= is reserved: it parses, but means nothing    |
| Range         | =(1..500)=, =(2 4 .. 10)=                      | see below                                          |
| Keywords      | =define/procedure=, =define/constant=, =graph= | see below                                          |

*** Booleans and null

Ouro has no null.
- =null= is an error where it is written, and no name.
- A name that only begins with it, =null-result=, is a name.

*** Symbols

A symbol starts with one of:
- a letter;
- one of the operator characters ~_ + - * / < > = ! & | ~~;
- one of the symbols of logic and sets ~¬ ∧ ∨ ⋀ ⋁ ∀ ∃ ∄ ∪ ∩ ∖ ⊆ ⋃ ⋂ ⊨~.

It may also contain digits, ~?~ and ~'~, and =:= after its first character. On its own, each symbol of logic and sets, like =λ=, is read as the name it stands for. See [[*Functions: =define/procedure=, =fn= and calls][functions]].

*** Attributes

An attribute is letters, digits, =-= and =_=, after an optional =@=. It may hold =:= after its first character, so a compact IRI is one key.

*** Properties

=#uri=, =#date=, =#string=, =#number=, =#boolean=, =#record=, =#array= and =#function= are the built-in properties.

- Any other name that begins with a letter, =#titled=, is read whole as a property defined in Ouro.
- So is a qualified one, =#people/titled=.
- Nothing checks one yet, so it is =Unknown property: #people/titled=.

*** Ranges

=..= is read after one or two expressions and before one, alone in their parentheses. Anywhere else it is an error.

*** Keywords

The keywords are =define/procedure=, =define/constant=, =define/property=, =graph=, =import= and =export=.

- A definition names its kind.
  - =define= on its own, or of another kind (=define/graph=), is an error.
  - Its message: ='define' is not a definition: say what is defined, …=.

- =defn=, =defn/const= and =defn/property=, which these replace, are errors that name their replacement.
  - =defn is now define/procedure: …=.

- A name that only begins with one of them, =defined=, =defnode=, =defn/constant=, is a symbol.

- =define/property= is read, but is not yet a form, so it is an invalid top-level keyword.

- No import is qualified =define= or =defn=, since its functions would read as these.
  - ~(import lib/define)~ is an error, and ~as define~ and ~as defn~ are not names.

*** Source files

A source file is UTF-8, on every platform. A letter is any Unicode letter, so =café= is a name and =:naïve= a key, and strings hold any text. A leading byte order mark is dropped, and CRLF line endings become LF.

- A file that is not valid UTF-8 is an error, not garbled text.

- A file that cannot be read, such as one that does not exist, is an error too, rather than an exception.

- The library reads no files.
  - It decodes the bytes it is given (~Data.Ouro.decodeSource~).
  - The command line reads them (~CLI.Source.readSource~).

- A file that ends with a delimiter still open is =SYN0001=.
  - It is reported at the innermost delimiter still open, in the file it is in.
  - "Expected: ')' to close this; Got: the end of the file".

- The compiler's messages are UTF-8 too.
  - On Windows, the console's code page is switched to UTF-8 (65001) while =ouro= runs, and restored when it exits.

*** Names

Names live in one namespace: values and functions share it. Shadowing is allowed, an inner value shadows an outer function of the same name.

- A trailing =!= on a function name is allowed, but has no meaning.

A =define/procedure= may take the name of a built-in, as a definition can in Scheme. It replaces the built-in throughout the file:

- In calls;
- In =case= guards;
  - under any symbol the built-in is also written with, so ~(define/procedure = ...)~ replaces =eq=.
- The compiler warns when it does (=WRN0003=).
- It may take a special form's name too, and shadows the form throughout the file, with the same warning.
  - The exception is the forms read by their syntax (see [[*Special forms][special forms]]).

A =/= qualifies an imported name, =base/aat=. So a =define/procedure=, a parameter or a =let= binding cannot have one.

- =/= and =/== themselves are names, being unqualified.

Functions and graphs are named in kebab-case, =make-place=. A name with a capital or an underscore is a warning (=WRN0004=) that suggests the kebab-case spelling.
- So =makePlace= and =make_place= are both =make-place=.
- Attribute keys and local bindings are exempt, since keys follow the data's vocabulary (=:_label=).

A =define/procedure= of no parameters, ~(define/procedure c () value)~, is a constant.
- It is worked out once per graph, whichever keyword defines it, with a return type or without.
- So it is a warning (=WRN0006=) that suggests ~(define/constant c value)~.
- The parsed tree does not keep which keyword was written, so the linter finds it in the tokens.

** Formal grammar (EBNF)

The grammar below describes the language accepted by the parser and evaluator together. Several productions share the same parenthesised notation, [[*Structural classification][Structural classification]] decides which one a form is.

#+BEGIN_SRC ebnf
(* ---------- Modules ---------- *)
(* imports and the export come first *)
module       = { import } , [ export ] , { import } , { declaration } ;
import       = "(" , "import" , module-path , [ "as" , symbol ] , ")" ;
(* names joined by "/", on every platform: std/base, linked-art/v1/people *)
module-path  = symbol ;
(* at most one, naming the module's own functions *)
export       = "(" , "export" , symbol , { symbol } , ")" ;
declaration  = procedure | constant | graph ;
procedure    = "(" , "define/procedure" , symbol , [ property ] , params , [ doc ] , expression , [ doc ] , ")" ;
(* a procedure of no parameters *)
constant     = "(" , "define/constant" , symbol , [ property ] , [ doc ] , expression , [ doc ] , ")" ;
(* at most one, before or after the result *)
doc          = "(" , "doc" , string , ")" ;
graph        = "(" , "graph" , symbol , expression , ")" ;
(* a property types the parameter after it *)
params       = "(" , { [ property ] , ( symbol | param-pattern ) } , ")" ;
(* binds the parts of one argument *)
param-pattern = record-pattern | array-pattern ;

(* ---------- Expressions ---------- *)
expression   = literal | asserted | symbol | record | array | call | special-form ;

literal      = string | number | "true" | "false"
             | "#record-empty" | "#array-empty" | "(" , ")" ;
asserted     = property , expression ;
property     = "#uri" | "#date" | "#string" | "#number" | "#boolean" | "#record" | "#array" | "#function" ;

(* A record: at least one attribute pair or context *)
record       = "(" , { record-item } , ")" ;
record-item  = attribute-pair | context | inlay ;
attribute-pair = attribute , expression ;
(* "@" makes a JSON-LD keyword, :@id *)
attribute    = ":" , [ "@" ] , key ;

(* An array: a form whose first element is not a symbol, or an explicit list *)
array        = "(" , [ non-symbol-expr , { expression } ] , ")"
             | "(" , "list" , { expression } , ")" ;

(* A call: a form headed by an expression that evaluates to a function *)
call         = "(" , symbol , { expression | placeholder } , ")" ;
(* a call with placeholders is a function of them *)
placeholder  = [ property ] , hole ;

(* ---------- Special forms ---------- *)
special-form = let | fn | case | get | has | get-or | image | map | filter | quantifier | fold
             | insert | replace-at | inlay | with | adjoin | thread | connective | all-any | satisfies | thru ;
let          = "(" , "let" , "(" , { binding } , ")" , expression , ")" ;
binding      = "$" , symbol , expression ;
fn           = "(" , "fn" , [ property ] , params , expression , ")" ;
case         = "(" , "case" , expression , { branch } , "(" , "otherwise" , expression , ")" , ")" ;
branch       = "(" , ( pattern | guard | alternatives ) , expression , ")" ;
guard        = "(" , comparison , expression , ")" ;
alternatives = "(" , literal , { literal } , ")" ;
get          = "(" , "get" , expression , path-step , { path-step } , ")" ;
(* a key into a record, or a whole number indexing an array *)
path-step    = symbol | number ;
has          = "(" , "has" , expression , path-step , { path-step } , ")" ;
(* a record, then a default, then the path *)
get-or       = "(" , "get-or" , expression , expression , path-step , { path-step } , ")" ;
(* a record or an array, then its path: keys only *)
image        = "(" , "image" , expression , symbol , { symbol } , ")" ;
(* map, filter and the quantifiers: an array, then a function *)
map          = "(" , "map" , expression , expression , ")" ;
filter       = "(" , "filter" , expression , expression , ")" ;
quantifier   = "(" , ( "forall" | "exists" | "omits" ) , expression , expression , ")" ;
(* an array, the value to start from, then a function of the running value and an element *)
fold         = "(" , "fold" , expression , expression , expression , ")" ;
(* two operands *)
connective   = "(" , ( "and" | "or" ) , expression , expression , ")" ;
(* one array of Booleans *)
all-any      = "(" , ( "all" | "any" ) , expression , ")" ;
(* the value, then the property; at the head of a case branch, the property alone *)
satisfies    = "(" , "satisfies" , [ expression ] , property , ")" ;
(* a duration *)
thru         = "(" , "thru" , expression , ")" ;
with         = "(" , "with" , expression , { record-item | expression } , ")" ;
(* with's dual: adds to a key's values *)
adjoin       = "(" , "adjoin" , expression , { record-item | expression } , ")" ;
(* a value, then its steps *)
thread       = "(" , "->" , ( expression | placeholder ) , { expression } , ")" ;
(* insert and replace-at: the collection, the index, then the value *)
insert       = "(" , "insert" , expression , expression , ( expression | attribute-pair ) , ")" ;
replace-at   = "(" , "replace-at" , expression , expression , ( expression | attribute-pair ) , ")" ;
inlay        = "(" , "inlay" , expression , ")" ;
(* a JSON-LD context value *)
context      = ( ":context" | ":@context" ) , expression ;

(* ---------- Patterns (inside case, and as parameters) ---------- *)
pattern      = hole | record-pattern | array-pattern ;
hole         = "?" | "?" , name ;
rest-hole    = "?.." , name ;
record-pattern = "(" , { attribute , sub-pattern } , [ rest-hole ] , ")" ;
(* contains at least one hole *)
array-pattern  = "(" , { sub-pattern } , [ rest-hole ] , ")" ;
sub-pattern  = hole | record-pattern | array-pattern | expression ;
#+END_SRC

** Values

| Value    | Written as                                     | JSON    |
|----------+------------------------------------------------+---------|
| String   | ="Manet"=, =#string expr=                      | string  |
| Number   | =3000=, =#number expr=                         | number  |
| Boolean  | =true=, =#boolean expr=                        | boolean |
| URI      | =#uri "https://..."=                           | string  |
| Date     | =#date "1881-01-01T00:00:00Z"=                 | string  |
| Record   | =(:key value ...)=, =#record expr=             | object  |
| Array    | =(a b c)=, =(list a b c)=, =#array expr=       | array   |
| Duration | =(years 2)=, =(days 19)=                       | none    |
| Function | =(fn (x) ...)=, a procedure's name, =+=, =#function expr= | none    |

Durations and functions are values during compilation, but have no JSON form.
They must be consumed, added to a date or called, before they reach the output.

*** Built-in properties

- =#uri= checks that a string is a URI with a scheme.
- =#date= checks that a string is an ISO-8601 timestamp, =YYYY-MM-DDTHH:mm:ssZ=.
- =#string=, =#number=, =#boolean=, =#record=, =#array= and =#function= check the type of any expression.
  - =#function= accepts a =fn=, a =define/procedure= name or a built-in.
- An assertion on a value that is already a URI or a Date passes it through.
- Assertions are how URIs and dates, which look like strings in JSON, keep their meaning inside Ouro.

A value without the property it is typed with is reported with both properties, as they are written:
- "Expected data to have the property =#number=, got =#string= instead".
- For =#uri= and =#date=, the reason is given too, and the expected form is in the blurb:
  - "got a =#string= without a URI scheme";
  - "got a =#string= that is not a date".

** Records and arrays

*** Records

A record is a form containing =:key value= attribute pairs, or a context.
- Its attribute pairs are output in source order.
- They are also bindings: inside the record, an attribute pair's name refers to its value, in any order.
- Each key appears once: writing a key twice in the same record, or two contexts, is an error.
- A key always has a value.
  - A key followed by another key, or by the end of its form, is =SYN0011= at the key: ~(:type :_label "x")~.
  - Read as a value, the next key would take its pair into itself.
- A key can be a compact IRI, ~(:crm:P2_has_type ...)~, and a path names one the same way, ~(get r crm:P2_has_type)~.

#+BEGIN_SRC clojure
(:begin_of_the_begin #date "1848-08-01T00:00:00Z"
 :end_of_the_begin   (+ begin_of_the_begin (thru (days 19))))
#+END_SRC

*** Arrays

A form of values is an array.
A form headed by a symbol is a call, so an array whose first element is a variable is written with =list=:

#+BEGIN_SRC clojure
(1 2 3)            ; an array
(("Manet") 1)      ; an array whose first element is an array
(list artist 1)    ; an array whose first element is the value of 'artist'
(artist 1)         ; a call to 'artist' (an error if it is not a function)
#+END_SRC

- An array of one record is written with nested parentheses, ~((:type "Name" ...))~.
  - That is the usual Linked Art shape for =classified_as=, =identified_by= and similar properties.
- An array of one bound value is written with =list=, ~(list manet)~, since ~(manet)~ is a call.
- Arrays, like JSON arrays, can hold values of any type: ~(1 "a" (:k 1) (2 3))~.

*** Inlays are layers

=inlay= splices a record's attribute pairs into the surrounding record, but a key still appears once.
- An attribute pair written in the record wins over an inlaid one with the same key, wherever the =inlay= is.
- A later =inlay= wins over an earlier one.

#+BEGIN_SRC clojure
(define/constant base (:type "Type" :_label "Painting"))

(:_label "Spring" (inlay (base)))   ; {"_label": "Spring", "type": "Type"}
#+END_SRC

An inlaid record's context is layered the same way, by the context's =Monoid=.
- The record's =@context= is the inlays' contexts, in order, then its own written context, as one context array.
- JSON-LD applies a context array in order.
  - So the written context, applied last, overrides a term an inlay's context also defines.
  - A later inlay's context overrides an earlier one's.
  - Terms only an inlay defines stay in scope.
- The same context reaching a record twice in a row is written once.
  - As when an inlaid node and the record both name Linked Art's context.

#+BEGIN_SRC clojure
(define/constant c (:context "https://a.org/c.json" :a 1))

((inlay (c)) :context "https://w.org/c.json" :b 2)
; {"@context": ["https://a.org/c.json", "https://w.org/c.json"], "a": 1, "b": 2}
#+END_SRC

** Bindings: records and =let=

There are two ways to bind a name, with a difference in serialisation:

| Form                          | Binds          | Output?                | Scope                         |
|-------------------------------+----------------+------------------------+-------------------------------|
| =(:name expr ...)= (a record) | its fields     | yes, every field       | the record's own expressions  |
| =(let ($name expr ...) body)= | its bindings   | no, only =body=        | the bindings and =body=       |

Both are recursive, as =letrec= is: the bindings can refer to each other in any order, and a cycle is an error. An inner binding shadows an outer one, but a binding is always evaluated in the scope where it was written:

#+BEGIN_SRC clojure
(let ($artist "Manet"
      $painted-by artist)                 ; written here, so "Manet"
  (:provenance (:artist     "Proust"
                :owner      artist        ; the inner 'artist': "Proust"
                :painted-by painted-by))) ; still "Manet"
#+END_SRC

*** A binding never sees itself

Inside its own expression, a binding's name refers to the enclosing scope.
- In ~(:name name)~, the attribute pair outputs the =name= from outside the record.
- In ~(let ($x (+ x 1)) x)~, the =x= being added to is the outer one.
- This is what makes templates such as ~(define/procedure node (id type) (:id id :type type))~ work.
- A name with nothing outside is unbound.
- Siblings that refer to each other in a cycle are still an error.

*** =let=

A =let= binds private values with =$name value= pairs.
- The =$= marks a binding that is never output, as =:= marks a key that is.
- A =:key= in a =let='s bindings is an error.
- So is a =$name= anywhere outside them: a binding is referred to by its bare name.

** Functions: =define/procedure=, =fn= and calls

| Form                                 | Meaning                                                             |
|--------------------------------------+---------------------------------------------------------------------|
| =(define/procedure name (x y) expr)= | a named function; top level only; visible throughout the file       |
| =(fn (x y) expr)=                    | an anonymous function value, closed over the scope it is written in |
| =(f a b)=                            | a call: =f= is any expression that evaluates to a function          |

Both kinds of function take an optional signature:
- =(define/procedure name #type (#type x y) expr)=;
- =(fn #type (#type x) expr)=.

*** =λ= and the symbols of logic and sets

=λ= is another way to write =fn=: ~(λ (x) (+ x 1))~.
- The lexer reads =λ= on its own as =fn=, so it is =fn= everywhere, and messages name it =fn=.
- Like =fn=, it can name a function or a binding, which then shadows =fn=.
- A longer name that begins with it, such as =λx=, is an ordinary symbol.

The symbols of logic and sets are read the same way, as the names they stand for:

| Symbol | Name  | Symbol | Name        | Symbol | Name            |
|--------+-------+--------+-------------+--------+-----------------|
| =¬=    | =not= | =∀=    | =forall=    | =⊆=    | =subset=        |
| =∧=    | =and= | =∃=    | =exists=    | =⋃=    | =unions=        |
| =∨=    | =or=  | =∄=    | =omits=     | =⋂=    | =intersections= |
| =⋀=    | =all= | =∪=    | =union=     | =⊨=    | =satisfies=     |
| =⋁=    | =any= | =∩=    | =intersect= | ~=~    | =eq=            |
|        |       | =∖=    | =setminus=  | ~/=~   | =neq=           |

- ~(∀ xs (> ? 0))~ is ~(forall xs (> ? 0))~, and messages name the word.
- A longer name that begins with a symbol, such as =∧x=, is an ordinary symbol.

*** Local functions

A local function is a =let=-bound =fn=:

#+BEGIN_SRC clojure
(let ($attribute (fn (label) (+ label " (attributed)")))
  (:attributed (attribute (attribute "Manet"))))
#+END_SRC

*** The body

A function's body is one expression, written exactly as it would be anywhere else, and its value is the result. The body can include a =let=, so a function binds its private values the same way a graph does.

- Parentheses around values make an array, so ~(fn () ("hello"))~ returns ~["hello"]~.
  - The compiler warns (=WRN0002=) when a result is a single plain value in parentheses.
  - A return type of =#array= says the array is intended, and silences it.

- A =define/procedure= body is checked when the file is parsed.
  - Apart from its =doc=, it must be one expression.
  - It cannot be a spliced record: ~(define/procedure f (x) :k v)~.
  - A nested =define/procedure= in it is reported with its replacement, a =let=-bound =fn=.

*** Documentation

A =define/procedure= is documented with a =(doc "...")= among the direct elements of its body.

- It goes before or after the result: ~(define/procedure place #record (#string slug #string label) (doc "A Linked Art Place.") (base/tgn ...))~.

- The parser takes it out of the body and keeps it with the function.
  - It is never evaluated, and it is not part of the result.

- A function has at most one, holding a single string.

- A =doc= anywhere else is an error: inside a result, in a =fn=, or in a graph.
  - It is reported when the file is parsed, so it is found even in a function that is never called.

- =doc= cannot name a function.

*** Arity

A call with the wrong number of arguments is an error. Functions are not curried.

- A call written with a function's name is checked before evaluation, wherever it is written.
  - The function is the module's, one an import exports, or a built-in.
  - This holds even in a function no graph calls.

- A function reached through a value, a parameter, a =let= binding or =map= is checked when it is called.

- A built-in's number of arguments is listed with it (~Builtins.builtinArity~), with the hint for a wrong one.
  - The evaluator gives the same hint.
  - A binding of its name, or a function of the module, is its own, as in Scheme.
  - A test checks that every built-in Ouro can write is listed.

*** Constants: functions of no parameters

A function of no parameters, named, is its value: a constant.

- =vocab/artwork= written as a value is =(vocab/artwork)=.

- This holds for a =define/procedure=, an imported function, and a =let=-bound =(fn () …)=.

- Ouro has no effects, so such a function cannot be told from its value.
  - This is Haskell's reading of a definition of no arguments.
  - Other Lisps keep a constant (=def=) apart from a procedure.

- ~(define/constant c value)~ writes one.
  - It is ~(define/procedure c () value)~, and takes a return type and a =doc= as a =define/procedure= does.

It is evaluated as the call is.

- So its return type, the blame for an error in its body, and the recursion check apply.

- =(define/procedure a () a)= is recursion.

At the head of a call, a name is the function itself.

- So =(c)= still calls it, and =(c 1)= and =(-> x c)= are arity errors.

- A call, =(c)=, is evaluated each time.

A function of no parameters cannot be passed as a function.

- =(map xs c)= receives its value, and =(satisfies c #function)= is =false=.

- An expression that evaluates to such a function without naming it is not called.
  - As a =case= that returns =(fn () 3)=.

When it is evaluated:

- one that closes over its module's root frame alone, as every =define/procedure= does, is evaluated once;
  - that is the first time it is named in a graph's evaluation;
  - that value is every later use's: nothing it can see varies;

- a =(fn () …)= written inside a function closes over a frame each call binds afresh;
  - so it is evaluated each time it is named;
  - ~(define/procedure make (x) (let ($k (fn () x)) k))~ gives =1= for ~(make 1)~ and =2= for ~(make 2)~;

- each graph is evaluated on its own, so a constant is evaluated once per graph that names it.

*** Arguments are call-by-need

Each argument becomes a promise over the caller's scope.

- It is evaluated at most once, when the function first uses it.

- It always means what it meant at the call site, so a function's own bindings can never capture it.

- An argument the function never uses is still evaluated when the graph is finished, so its errors are reported.

*** Closures

The body is evaluated in the function's closure, extended with a frame for the parameters.

- For a =define/procedure=, the closure is the module.

- For a =fn=, it is the scope where the =fn= was written.

A function cannot see its caller's bindings.

*** Recursion goes down into a value

A function may reach itself by its name, directly or through others, only if it goes down into a value each time round. This means that functions always terminates: values are finite trees, so a call that always passes on a part of a parameter reaches the leaves.

The static analysis checks it as Lee, Jones and Ben-Amram's size-change termination (2001) does.

- Each call relates the size of each argument it passes to the caller's parameters: a part (smaller), or no larger.

- Every way round a circle of functions, followed until it repeats itself, must pass some parameter a part of itself.

- So ~(define/procedure f (a b) (f b (get a k)))~ is accepted, its arguments changing places.
  - Every second time round, =a= is passed a part of itself.

A part of a parameter is:

- a path into it, ~(get n part)~;

- a hole of a pattern matched against it, in a =case= branch or a parameter;
  - except a rest hole alone in its pattern, ~(?..t)~, which may be all of it;

- an element of it, or of a path into it, passed to a function by =map=, =exists=, =forall=, =omits= or =filter=;
  - named there, ~(map xs walk)~;
  - or as a =fn= written there, ~(map (get-or n () part) (fn (p) (walk p)))~;

- a =let= binding or attribute pair holding one.

No larger is:
- the parameter itself;
- ~(get-or n () part)~, which may be its fallback each time;
- =image= and =filter= of it.

Anything else is of unknown size: a computed value, a literal, a number counting down.

A circle that might not finish is an error, whether or not anything calls it. It is reported once, at the name that closes it, the last written. So a file reads the same wherever it was saved.

- ~(define/procedure f (n) (h n)) (define/procedure h (n) (f n))~ is reported at the =f= in =h=.
  - ='f' calls itself, through f → h → f, and might never finish=.

A function by name is a =define/procedure=, or a =fn= bound by a =let= binding or an attribute pair. A binding never sees itself, so such a =fn= names itself only through a sibling. Its name written in it counts: called, passed on, or in a pattern's values and a name not called has arguments of unknown size.

- So a =fn= a function returns may not name the function, though calling it could finish.

- A =fn= bound by name has parameters of its own.
  - The parameters of the function around it are of unknown size in it.

A function reached through a value is checked when it is called.

- That is a parameter, or a function a call returns, as in a self-application ~(w w)~.

- Calling a function that is already being called is an error.
  - A function is identified by its name and its definition's position.

- Nesting a call, ~(f (f x))~, is two calls, not recursion.

A call the analysis accepted runs, though its function is already being called, and it alone.

- The evaluator knows it by where the function's name is written.

- So a function that goes down into a value, but is also given itself through a parameter, is stopped there.
  - ('walk' called itself through a value).

- Its arguments are evaluated first, and an error in one is the call's value, ending the recursion.
  - An error is no part of a value.
  - So ~(define/procedure f (n) (f (get n part)))~ stops with =get='s error once a =part= is missing.

- This changes no output: an argument a graph never needs is evaluated anyway, for its errors (see No hidden errors).

*** Functions are values

Functions can be passed as arguments and returned.

- They cannot be compared: =eq= on functions is a type error.
- They cannot be serialised.

A returned function is called through =let=.

- A form headed by a call is an array, so ~((f x) y)~ does not call the result of ~(f x)~.
- Bind it first: ~(let ($g (f x)) (g y))~.
- A function can return a =fn= waiting for the remaining arguments, or a [[*Placeholders][placeholder]], ~(+ ? n)~:

  #+BEGIN_SRC clojure
  (define/procedure adder (n) (fn (x) (+ n x)))

  (graph g
    (let ($inc (adder 1))
      (:r (inc 2))))              ; {"r": 3}
  #+END_SRC

*** Signatures

A function's types are built-in properties in its header. One between the name and the parameters is the return type. One before a parameter is that parameter's type.

- Either can be left out, and so can any parameter's.

#+BEGIN_SRC clojure
(define/procedure node #record (#uri id type)
  (:id id :type type))

(let ($double (fn #number (#number n) (* n 2)))
  (:r (double 21)))               ; {"r": 42}
#+END_SRC

- The types are the built-in properties.
  - =#string=, =#number=, =#boolean=, =#uri=, =#date=, =#record=, =#array= and =#function=.

- There is one sigil for types: =#= always names a property, and its position says what it applies to.

- A property in a signature behaves exactly as it would anywhere else.
  - It checks the value, and =#uri= and =#date= convert a string.
  - In =node= above, =id= arrives as a URI.

- Each argument is checked where the call is written, so a mismatch is reported at the argument, in the call.

- The result is checked where the body is, and a mismatch is reported there.

- An argument is checked even if the function never uses it.

- Nothing is inferred: an untyped parameter or result is not checked, and unannotated code behaves as before.

Signatures are checked when values cross them.

- The caller's arguments must have the parameters' properties, and the function's result its return property.

- A signature is checked when a value crosses it, not before evaluation, as a static type is.

- A failed check is reported where the value came from.
  - A bad argument at the call.
  - A bad result at the function's body.

- Ouro evaluates everything at compile time, so the checks cost nothing in the output.
  - Every one has run before the document is written.

*** Placeholders

A call with =?= holes among its arguments is not called.
- It is a function of its holes, and the arguments it is given fill them in.

#+BEGIN_SRC clojure
(define/procedure node (id type) (:id id :type type))

(graph g
  (let ($inc      (+ ? 1)                  ; (fn (a) (+ a 1))
        $painting (node ? "Painting")      ; (fn (a) (node a "Painting"))
        $square   (* ?n ?n))               ; (fn (n) (* n n))
    (:r (inc 41)
     :s (painting "https://a.org/1")
     :t (square 7))))
; {"r": 42, "s": {"id": "https://a.org/1", "type": "Painting"}, "t": 49}
#+END_SRC

- *Each =?= is a parameter*, in the order the holes are written.
  - ~(- ? ?)~ takes two arguments, the first to subtract from.
- *A named hole is one parameter*, however often it is written: ~(* ?n ?n)~ takes one.
  - Parameters follow the order in which each hole is first written, so ~(+ ?a ?b ?a)~ takes =a= then =b=.
- *A typed hole is a typed parameter*.
  - ~(node #uri ? "Painting")~ checks, and converts, its argument as a signature would.
  - A mismatch is reported at the argument where the placeholder is called.
  - An untyped hole passed to a typed parameter of the function is checked by that function.
  - A mismatch is then reported at the hole.
- *A hole belongs to the call it is an argument of*.
  - So ~(* 2 (+ ? 1))~ multiplies 2 by a function (an error), and ~(f (g ?))~ passes =f= a function.
- *Any call takes holes*:
  - a =define/procedure=, a =fn=, a built-in, and an operator (~(< ? 10)~);
  - the special forms that evaluate their arguments;
    - =get=, =image=, =insert=, =replace-at=, =list=, =map=, =fold=, =->=.
  - The forms with their own structure do not: =let=, =fn=, =case=, =context=, =inlay=, =thru=.
- *A placeholder is a value*: it is a =fn=, closed over the scope it is written in.
  - So it can be bound, passed and returned like one.
  - It is called with exactly as many arguments as it has holes.
- *A hole anywhere else is an error*: in an array, in a record, or as a binding's value.
  - A rest hole, =?..name=, only matches the rest of an array or record, so it can only be written in a pattern.
  - That is a =case= pattern or a [[*Destructuring parameters][parameter]].

The holes in a =case= pattern are not placeholders: they match values (see [[*=case= and patterns][patterns]]).
- A placeholder can be written in a branch's body.

*** Destructuring parameters

A parameter can be a pattern, written as a =case= pattern is. It takes one argument and names its parts:

#+BEGIN_SRC clojure
(define/procedure label-of ((:_label ?l)) l)

(graph g
  (:people (map (("allan" "Scott Allan") ("beeny" "Emily Beeny"))
                (fn ((?slug ?label)) (:id slug :_label label)))
   :label  (label-of (:type "Type" :_label "Beauty"))))
; {"people": [{"id": "allan", "_label": "Scott Allan"}, {"id": "beeny", "_label": "Emily Beeny"}],
;  "label": "Beauty"}
#+END_SRC

- *A pattern is one parameter*: ~(fn ((?a ?b)) ...)~ takes one argument.
  - Names and patterns can be mixed: ~(define/procedure sum (base (?a ?b)) ...)~.

- *Any pattern* can be written:
  - array patterns;
  - record patterns, open, as in =case=;
  - =?..rest= holes;
  - values compared by value, as in ~(fn (("Person" ?l)) l)~.
  - A pattern must bind something, so it is a record pattern or holds a hole.

- *It is matched when the function is called*, even if the body uses none of its holes, as a typed argument is checked.
  - The holes are bound in a frame around the body.

- *A mismatch is the caller's*: it is reported at the argument in the call, or at the array in =map=.

- *A property before a pattern* checks the argument first: ~(fn (#array (?a ?b)) ...)~.

- *Each name is bound once*: two parameters, two holes, or a hole and a parameter with the same name are an error.
  - It is reported where the function is defined.

- *A pattern's values are evaluated where the function is defined*.
  - A =define/procedure='s pattern sees the module's functions.
  - A =fn='s sees the scope it is written in.
  - Neither sees the function's other parameters: a check against another is written in the body, with =case=.

- *Placeholders leave parameters alone*: a =fn='s parameter list is not read as calls.
  - So a hole in it is always a pattern's.

** Special forms

Special forms are recognised by their head symbol.

*** Their names are bindings

Their names are bound like any other, as in Scheme, which has no reserved words.

- A binding around a form shadows it, and the form is then an ordinary call of the binding.
  - That is an attribute key, a =let= binding, a parameter, a hole, or a =define/procedure= of the module.
  - ~(let ($list (fn (x) (+ x 1))) (list 1))~ is =2=.

- A key is a binding whose value is also written out, and a value written out cannot be a function. So a call of a form a key shadows is an error that says so: ~(:image "x" :r (image y part))~ calls the string ="x"=.

- The forms Canon writes are not the source's, and use heads no source can spell: =%case=, =%let=, =%fn= and =%inlay=, so no binding captures them. ~(let ($case 1) (or a b))~ is still =or=. This is hygiene, as a Scheme macro's =if= means the core =if=.

The exception is the forms Canon rewrites by their syntax, before any name is bound:

- =and=, =or=, =->=, =with=, =adjoin= and =thru=;
- a =case= branch's =(when c)= and =(satisfies #p)= heads.

A binding of one of their names is ignored where Canon reads the form (gap 45). A =define/procedure= cannot take their names, since it could never be called by them (=SYN0008=), nor the declarations' names: =define/procedure=, =graph=, =doc=.

*** The subject first

Every form and built-in takes the value it works on first:

- the record of a path;
- the array of =map= and the quantifiers;
- the collection of =insert=;
- the value =satisfies= asks about.

So =->=, which threads a value in as the first argument, threads through every one of them without a hole, and a =case= guard, which inserts its target first, is a comparison or =satisfies= alike.

A question is written as membership is, the element or the domain first: ~(satisfies x #p)~ is x ∈ #p, and ~(forall xs f)~ is ∀x ∈ xs. f(x). The statement =#p x= puts the property first, as P(x) does.

*** The forms

*** =insert= and =replace-at=

- Negative indexes count from the end, as in a path.

- =insert= puts any value into an array, but not a =:key value= attribute pair.

- Neither can give a record a key it already has: that is an error. =replace-at= may keep the replaced attribute pair's own key.

*** =get=

=get= evaluates its target and walks the resulting records, so it works through function results, =inlay=, =case= and =let= alike. Only a record's attribute pairs can be reached: =let= bindings are private.

Path components are bare symbols or whole numbers: =(get p q r)=, not =(get p :q)=.

- A number indexes an Array, counting from 0, and a negative one counts from the end.
  - ~(get p classified_as 0 _label)~ is the label of the first classification.
  - ~(get xs -1)~ is the last element.

- An index is written, never computed, and indexes only Arrays. A record's attribute pairs are reached by key, never by position, since JSON-LD gives them no order.

- An index past the end is an error. So is an index into anything that is not an Array, or a key into an Array, and the error says to write an index or use =image=.

- A hole can stand for the target, ~(get ? 0)~, but not for a key or an index: a path never depends on the values it is given.

*** =map=

~(map array f)~ evaluates =array= and =f=. The array comes first, as every form takes what it works on first, so =->= threads through =map=. The result is an array of =f= called on each element, in order.

- =array= must be an array: =()= and =#array-empty= are empty arrays.
- =f= must be a function: a =fn=, a =define/procedure= name, a built-in or a placeholder.

Each element is passed as an ordinary call, made in a frame that binds the function and the element to names that cannot be written in Ouro. So arity, signatures and the recursion check apply as they do to any call:

- =f= must take one argument;
- a typed parameter checks every element;
- a mismatch is reported at the array, since an element has no position of its own.

With placeholders, ~(map xs (+ ? 1))~ needs no =fn=, and ~(map ? f)~ is a function waiting for the array. Elements that are themselves arrays or records are taken apart by a [[*Destructuring parameters][pattern parameter]]: ~(map pairs (fn ((?k ?v)) ...))~.

=map= is a special form only at the head of a form. A binding of =map= shadows it there: a key, a =let= binding or a =define/procedure=.

*** =exists=, =forall=, =omits= and =filter=

Each calls =f= on the elements of an array exactly as =map= does, with the same arity, signature and recursion rules. The array is the domain, written first as in ∀x ∈ xs. f(x). They take holes: ~(exists ? (> ? 2))~.

- =f= must answer =#boolean=; an answer that is not a Boolean is reported at the array.

- =exists=, =forall= and =omits= stop at the element that decides the answer, as =or= and =and= stop at an operand. So ~(exists (1 "x") (> ? 0))~ is =true= without calling =f= on ="x"=.

On an empty array:

- ~(exists () f)~ is =false=;
- ~(forall () f)~ and ~(omits () f)~ are =true=;
- ~(filter () f)~ is =()=.

~(omits xs f)~ is ~(not (exists xs f))~, the quantifier =∄=. It is named for what the data omits, not for what does not exist. A document's silence is not a complete observation, so =omits= says only that the array has no such element, never that no such thing exists.

#+begin_example
(omits (get-or book () tp46) (contains (get-or book () ntp46) ?))
#+end_example

This contradiction check says no type is recorded as both present and absent.

*** =has= and =get-or=

Both walk a path as =get= does, and both need at least one key.

- ~(has record key ...)~ is =false= when a record on the way has no such key, or an Array no such index.

- ~(get-or record default key ...)~ is then =default=, which is evaluated only in that case.

- Anything else that stops the walk, a value on the way that is not a record or an error, is reported as =get= reports it.

*** =image=

~(image record key ...)~ reads a path as JSON-LD reads properties, as sets of values: ~(image book part classified_as)~ is every classification of every part.

At each key:

- a record gives that key's values: an Array is its elements, any other value is one value;
- an Array gives the key's values from each of its elements;
- a record without the key adds nothing, so ~(image book tp46)~ is =()= when there is no =tp46=.

The result is always an Array with no repeats. Values are compared as =eq= compares, and kept in the order first reached, as =union= keeps them.

- A value on the way that is not a record is an error, an Array inside an Array among them. So is the first error reached.

- Following =id= compares by identity rather than by value. ~(image book part classified_as id)~ is a set of IRIs, so one type written with two labels is one element.

- Like =get=, it needs at least one key and takes bare symbols as path components. It takes no indexes, since a set has no positions.

Use =get= where the data has one value by construction, and =image= for anything JSON-LD reads as a set. A missing key gives =()= rather than an error, so a misspelt key gives an empty set.

*** =satisfies=

~(satisfies x #p)~ is a question, where =#p x= is a requirement. It answers =false= when =x= does not have the property, where =#p x= is an error. Only the property's own check gives =false=: an error inside =x= stays an error.

A property written on its own, with nothing after it, is meaningful only at the head of a =case= branch. There, in ~(satisfies #p)~, the case's target fills it in; anywhere else it is an error. There the head is read by its syntax; elsewhere a binding or a =define/procedure= of =satisfies= shadows it.

*** =with= and =->=

~(with base item ...)~ is =base= with =item=s written over it, layered as an =inlay= is. A written attribute pair wins over the base's own, and an array base has its elements spliced, so ~(with (1 2) 3 4)~ is ~(1 2 3 4)~. With nothing to add, ~(with base)~ is =base=.

~(-> x step ...)~ threads =x= through its steps, each receiving the value before it:

#+BEGIN_SRC clojure
(-> (base) (with :type "Mine") (with :_label "L"))   ; (with (with (base) :type "Mine") :_label "L")
(-> 1 (- 10))                                       ; (- 1 10): the value goes first
(-> 1 (- 10 ?))                                     ; (- 10 1): or where a hole marks it
(-> 1 wrap)                                         ; (wrap 1): a bare name is called with it
(-> 5 (case ((> 3) "big") (otherwise "small")))    ; special forms are steps too
#+END_SRC

- *A step* is called with the value as its first argument.
  - A bare name is called with the value.
  - A step that is a function, such as a placeholder ~(- 10 ?)~ or a =fn=, is called with the value.
  - A step receives exactly one value, so ~(+ ? ?)~ is an arity error.
  - A step that is not a function is a type error.

- *=(-> ? step ...)=* is a function of the value, by the placeholder rule: ~(map records (-> ? (with :seen true)))~.

- ~(-> x)~ is =x=.

- =with= and =->= are rewritten by their syntax before any name is bound (see /Canon-Desugaring/). So they cannot name a =define/procedure=, and a binding of either is ignored at a call (gap 45).

*** =adjoin=

~(adjoin base item ...)~ is =with='s dual: the same shape, and the same place in =->= and under placeholders. Where =with= sets a key, =adjoin= adds to the key's set of values, as JSON-LD reads a property. So =with= suits a property that holds one value (=_label=, =produced_by=), and =adjoin= one that holds a set (=classified_as=, =identified_by=):

#+BEGIN_SRC clojure
(adjoin (:k 1) :k 2)                  ; {"k": [1, 2]}: a single value becomes a set
(adjoin (:k (1 2)) :k 2)              ; {"k": [1, 2]}: a value already there is not added
(adjoin (:k (1)) :k (list 2 3))       ; {"k": [1, 2, 3]}: a list adds its elements
(adjoin (:k (1 1)) :k (1 3))          ; {"k": [1, 1, 3]}: the values there are kept as they are
(adjoin (1 2) 2 3)                    ; (1 2 3): an array adds the elements not there
(-> (:type "Place") (with :_label "Amsterdam") (adjoin :classified_as (city)))
#+END_SRC

- *A value is added unless it is already there*, compared as =eq= compares, by value. Two records are the same value when their attribute pairs are, so one entity written with two labels is two values.

- A key that is added to always holds an Array, even of one value. The values already there are not touched, repeats included.

- *A key keeps its place* in the record, and a new key goes after the others. (=with= puts a key it writes after the base's.)

- *Items* are as =with='s: attribute pairs, a context, which is layered as =with= layers it, and =(inlay x)=, whose attribute pairs (or elements) are adjoined. A key written twice in one =adjoin= is an error, as in a record.

- *The base* decides: a record takes attribute pairs, an array takes elements. Anything else is a type error, as are attribute pairs adjoined to an array and an element adjoined to a record. A function among the values cannot be compared, so it is an error, as in =union=.

- ~(adjoin base)~ is =base=, and adjoining the same values twice is adjoining them once.

- =with= after =adjoin= sets the key; =adjoin= after =with= adds to it.

- =adjoin= is rewritten by its syntax before any name is bound. So it cannot name a =define/procedure=, and a binding of it is ignored at a call (gap 45).

** =case= and patterns

#+BEGIN_SRC clojure
(case target
  (("Manet" "Proust") "person")   ; alternatives: equal to any of the literals
  ((> 100)            "large")    ; a guard: (op args...) with target as first argument
  ((?head ?..rest)    rest)       ; an array pattern
  ((:type "Person" :_label ?l) l) ; a record pattern
  (otherwise          "other"))
#+END_SRC

The target is evaluated once; the branches are tried in order and the first match is evaluated. A branch head is:

- =otherwise=: always matches; it is required, and must be the last branch.

- *A guard*, a form headed by a comparison: ~>~, ~>=~, ~<~, ~<=~, =eq=, =neq=. The target is inserted as the comparison's first argument, so ~((< 10) e)~ tests ~(< target 10)~. A comparison takes two operands, so a guard takes one: ~((< 10 20) e)~ is an arity error, and two bounds are a =when= over =all=, ~((when (all ((> x 1) (< x 10)))) e)~.

- *A condition*, ~(when cond)~: =cond= must have the property =#boolean=; =true= takes the branch and =false= tries the next. It can use any value in scope, not only the target, but not the names a pattern binds. =when= is only a branch head, where it is read by its syntax; elsewhere a binding or a =define/procedure= of =when= shadows it.

- *A property*, ~(satisfies #p)~ or ~(⊨ #p)~: the target satisfies the property =#p=, as ~(satisfies target #p)~ asks. The target is inserted first, as for a comparison.

- *A pattern*, a record form or a form containing a =?= hole (described below).

- *Alternatives*, a form of literals: sugar for one branch per literal.

- *A literal*: compared with =eq=.

Patterns match /values/, written in Ouro's own construction syntax:

- *Record patterns*, =(:key pattern ... ?..rest)=, match by key in any order. They are open: extra attribute pairs are allowed, and =?..rest= binds them as a record.

- *Array patterns*, =(pattern ... ?..rest)=, match by position; =?..rest= must come last and binds the remaining elements as an array.

- *Holes:* =?= matches anything; =?name= binds the value.

- *Anything else* (literals, symbols, calls) is evaluated and compared by value, so ~((+ 2 4) ?x)~ and ~(6 ?x)~ are the same pattern.

Pattern variables are bound in a frame around the branch body. A record written in the body shadows them with its own attribute pairs.

** Built-ins

| Group        | Names                                     | Notes                                              |
|--------------+-------------------------------------------+----------------------------------------------------|
| Arithmetic   | ~+~ ~-~ ~*~ ~/~                           | two operands; many are folded, ~(fold xs 0 +)~     |
| Comparison   | ~eq~ ~neq~ ~>~ ~>=~ ~<~ ~<=~              | two operands; a chain is =all= over its pairs      |
| Extremes     | ~min~ ~max~                               | ~(max xs)~ of one Array of Numbers                 |
| Negation     | ~not~                                     | ~(not b)~ of one Boolean                           |
| Length       | ~len~                                     | an array's elements, or a string's characters      |
| Collections  | ~contains~ ~distinct~                     | ~(contains coll x)~; ~(distinct xs)~ drops repeats |
| Ranges       | =(1..5)= =(2 4 .. 10)=                    | whole numbers from start to end, both included     |
| Pairs        | ~zip~                                     | ~(zip xs ys)~ pairs two Arrays of one length       |
| Strings      | ~to-string~ ~split~ ~join~                | ~(to-string 42)~ is ="42"=                         |
| More strings | ~upper-case~ ~lower-case~ ~trim~          | each takes the String first, so =->= threads       |
|              | ~starts-with~ ~ends-with~                 |                                                    |
|              | ~slice~ ~pad-start~ ~replace-all~         |                                                    |
| Sets         | ~union~ ~intersect~ ~setminus~ ~subset~   | ~(union (1 2) (2 3))~ is ~(1 2 3)~                 |
| Big sets     | ~unions~ ~intersections~                  | over one array of arrays: ~(unions (map xs f))~    |
| Durations    | =years months days hours minutes seconds= | ~(days 19)~ is a Duration                          |
| End-of-unit  | =(thru d)=                                | ~(thru (days 1))~ = 1 day 23:59:59                 |

*** Arity and operators

Every built-in takes a fixed number of arguments, and many values are an array. An operator written with any number of operands but two is an arity error, whose hint is the fold.

- Ordering (~>~ ~>=~ ~<~ ~<=~) compares numbers only.

- =+= also joins strings and arrays, and adds durations to dates.

- A chain of comparisons is =all= over its pairs: ~(all ((< a b) (< b c)))~.

*** Strings

Each string built-in takes the String it works on first, so ~(-> label (trim) (upper-case))~ threads. A character is a Unicode code point, as for =len=.

~(to-string x)~ writes a String, a finite Number, a Boolean, a URI or a Date as text, exactly as the JSON output writes it: ~(to-string 123456789)~ is ="123456789"=, ~(to-string 4.9)~ ="4.9"=, a Date in ISO-8601 form. A Record or an Array is an error: build its text with =join=.

~(split s separator)~ is the pieces of =s= between each separator, an Array of Strings: ~(split "a, b" ", ")~ is ~("a" "b")~. A String without the separator is one piece, and two separators together give an empty piece. The separator is at least one character.

~(join strings separator)~ is the reverse: ~(join xs ", ")~ joins Strings. It takes an Array of Strings only (=(map xs to-string)= first for Numbers), and an empty Array joins to =""=.

The rest:

- ~(upper-case s)~, ~(lower-case s)~ and ~(trim s)~, which removes the white space at both ends.

- ~(starts-with s prefix)~ and ~(ends-with s suffix)~ answer a Boolean.

- ~(slice s start end)~ is the characters from =start= up to, not including, =end=. A negative index counts from the end, as in a path, so ~(slice "C-0042" 2 6)~ and ~(slice "C-0042" -4 6)~ are both ="0042"=. Indexes outside the String, or an end before the start, are an error.

- ~(pad-start s width fill)~ writes the one-character =fill= before =s= until it is =width= characters long: ~(pad-start "42" 4 "0")~ is ="0042"=. A String already that long is unchanged.

- ~(replace-all s old new)~ replaces every =old=, of at least one character, with =new=.

*** Numbers in the output

A Number is written as JavaScript writes one. =to-string= writes the same digits.

- A whole number is written as an integer: =123456789=.

- Any other, between 10^-7 and 10^21, is written in plain decimal with the fewest digits that read back as the same number: =0.1=, =0.00001=.

- Beyond that range, it is written in scientific notation: =1.0e21=.

*** =min= and =max=

~(min xs)~ and ~(max xs)~ are the smallest and largest Number of an Array, so a summary is worked out from the data rather than typed beside it: ~(:lower (min weights) :upper (max weights))~.

- They take one Array, as every built-in takes a fixed number of arguments. Several Numbers are written as one, ~(min (a b c))~, and anything but one Array is an error.

- Ordering compares Numbers only.

- An empty Array is an error: there is no smallest of nothing.

*** Ranges

~(start..end)~ is the whole numbers from =start= to =end=, both included, as Haskell's =[1..500]=: ~(1..5)~ is ~(1 2 3 4 5)~, and an end below the start gives =()=.

- Each end is an expression, ~(1..n)~, ~(1..(len xs))~, and must be a whole number.

- =..= is read only between the two ends of a range, alone in its parentheses: ~(1..2..3)~, ~(..5)~ and a =..= in a record are errors.

- It is a call of a built-in that cannot be written, =%range=, so ~(map (1..500) f)~ numbers 500 records without listing them.

Two numbers before =..= count in steps of their difference, as Haskell's =[2,4..10]=:

- ~(2 4 .. 10)~ is ~(2 4 6 8 10)~;
- ~(5 4 .. 1)~ counts down, ~(5 4 3 2 1)~;
- the end is included when a step lands on it: ~(1 3 .. 6)~ is ~(1 3 5)~;
- a step away from the end gives =()=;
- a step of 0 is an error.

*** =zip=

~(zip xs ys)~ pairs two Arrays element by element, each pair an Array of two: ~(zip (1 2) ("a" "b"))~ is ~((1 "a") (2 "b"))~. With a range it numbers a list, ~(zip (1..(len xs)) xs)~, and a pattern parameter takes each pair apart, ~(map (zip (1..(len xs)) xs) (fn ((?n ?x)) ...))~.

Arrays of different lengths are an error, rather than the longer one's last elements being lost. Haskell's =zip= stops at the shorter list, for zipping with an endless one; Ouro has none.

*** =and=, =or=, =all= and =any=

=and= and =or= are special forms that combine two Booleans, ∧ and ∨: ~(and a b)~ is =true= when both operands are, and ~(or a b)~ when one is. Any other number of operands is an error whose hint is the n-ary form.

=all= and =any= are the n-ary =and= and =or=, ⋀ and ⋁ (=⋀= and =⋁= are read as their names), over one array of Booleans, since many values are an array. ~(all ((has r _label) (has r classified_as)))~ is =true= when every element is, and ~(any (...))~ when one is; ~(all ())~ is =true= and ~(any ())~ is =false=.

Each evaluates in order, and stops at the operand that decides the answer, so ~(and false (get () 5))~ is =false=.

- Each operand it reaches must have the property =#boolean=. Unlike other Lisps, Ouro has no truthiness, and the result is always =true= or =false=.

- =all= and =any= stop only over an array written in place, a literal one or a =(list ...)=. That keeps the guard ~(all ((has r year) (> (get r year) 1600)))~ from reading a year =r= does not have. An array given any other way, a binding or a =map='s result, is evaluated whole, then read in order.

- A chain of comparisons is =all= over its pairs, and stops the same way: ~(all ((< 2 1) (< 1 (get () 5))))~ is =false=.

All four:

- are desugared into =case= (see [[*Desugaring (~Canon~)][desugaring]]);
- take holes like a call, ~(or ? x)~;
- cannot name a =define/procedure=, being rewritten before any name is bound (gap 45);
- cannot be passed as values, being special forms, so a hole is how one is made into a function.

*** =fold=

~(fold array init f)~ calls =f= on the running value and each element in turn, starting from =init=: a left fold. ~(fold (1 2 3) 0 f)~ is ~(f (f (f 0 1) 2) 3)~, and ~(fold () init f)~ is =init=.

- The array comes first, as every form takes what it works on, so =->= threads into it: ~(-> xs (map f) (fold 0 +))~.

- =f= takes the running value first, as ~(+ total w)~ and ~(adjoin set :member p)~ do.

- Each call is an ordinary call, as =map= makes one, so =f= takes exactly two arguments and its signature checks them. An error stops the fold, as its value.

- With =+= and =0= it is Σ, so ~(fold weights 0 +)~ sums an array.

*** =len=

=len= takes exactly one argument. It is an ordinary built-in, so ~(map xs len)~ works.

- An array's elements are counted whatever their types, so ~(len (1 (2 3) (:k 4)))~ is 3. =()= and =#array-empty= have length 0.

- A string is counted in characters (Unicode code points), not bytes, so ~(len "Málaga")~ is 6. A string cannot be taken apart in Ouro, so its length cannot be written in Ouro itself.

- Any other value, a record or a URI included, is a type error.

*** =contains=, =distinct= and =not=

- =contains= takes two arguments. ~(contains (1 2 3) 2)~ is =true= when the array has the value as an element, compared as =eq= compares, so records and arrays are compared by value. ~(contains "Amsterdam" "dam")~ is =true= when the string has the other as a substring.

- =distinct= takes one array and keeps the first of each value, in order: ~(distinct (1 2 1 3))~ is ~(1 2 3)~.

- An array holding a function is a type error for both, since functions cannot be compared.

- =not= takes one =#boolean=.

*** Sets

=union=, =intersect= and =setminus= treat arrays as sets, as JSON-LD reads a property's values. Elements are compared as =eq= compares them, so records and arrays are compared by value. A result has no repeats: the first of each is kept, in the order it is first written, so the output is always the same.

Each takes two arrays, as every built-in takes a fixed number of arguments:

- ~(union a b)~ is every value in either;
- ~(intersect a b)~ the values in both, in =a='s order;
- ~(setminus a b)~ the values of =a= not in =b=.

Many sets are an array of them, for =unions= and =intersections= below, and another number of arguments is an arity error that says so. An argument that is not an array, or an array holding a function, is a type error. They are ordinary built-ins, so they can be passed as values and take holes: ~(map groups (setminus ? excluded))~.

~(subset a b)~ takes exactly two arrays, and is =true= when every value of =a= is in =b=, a ⊆ b: that is when ~(setminus a b)~ is empty. ~(subset required (ids obj))~ checks that an object has every one of several classifications.

~(unions xs)~ and ~(intersections xs)~ are the union and intersection of one array of arrays, =⋃= and =⋂=, for sets that are computed rather than written: ~(unions (map parts (get ? classified_as)))~ is every classification of every part. ~(unions ())~ is =()=; the intersection of no sets is not defined, so ~(intersections ())~ is an error.

*** Dates and durations

Dates are shifted with =+= and =-=: ~(+ start (days 19))~. Shifting by months or years clips to the end of a shorter month instead of rolling over, so 31 March minus one month is the last day of February.

=thru= exists for Linked Art timespans, whose =end_of_the_end= is the last moment of a period: ~(thru (days 1))~ is 1 day 23:59:59, and ~(thru (years 0))~ is to the end of the current year:

#+BEGIN_SRC clojure
:begin_of_the_begin #date "1642-01-01T00:00:00Z"
:end_of_the_end     (+ begin_of_the_begin (thru (years 0)))   ; 1642-12-31T23:59:59Z
#+END_SRC

** =@context=

A record's JSON-LD context is written =:context value=. The value is an ordinary expression, and it is written as JSON-LD writes a context:

#+BEGIN_SRC clojure
(:context "https://linked.art/ns/v1/linked-art.json" ...)           ; a remote context
(:context (:@vocab "https://example.org/" :@language "en") ...)     ; a local context
(:context ("https://linked.art/ns/v1/linked-art.json"               ; several, applied in order
           (:ex        "https://example.org/ns/"
            :condition (:@id "ex:condition" :@type "@id")))
 ...)
#+END_SRC

*** A context is a value

A context is a remote context's URL (a String or a =#uri=), a local context record, or an array of them. Ouro has no null, so a context cannot clear another (=@context: null=), and no keyword or term is set to null.

It is evaluated like any other value, so a function can build one:

#+BEGIN_SRC clojure
(define/procedure linked-art () "https://linked.art/ns/v1/linked-art.json")

(:context ((linked-art) (:ex "https://example.org/ns/")) ...)
#+END_SRC

*** Local contexts

A local context holds keywords and term definitions. A key starting with =@= is a JSON-LD keyword, written =:@vocab=. The context keywords are:

1. =@vocab=
2. =@base=
3. =@language=
4. =@direction=
5. =@version=
6. =@protected=
7. =@propagate=
8. =@import=

Any other key defines a term, which maps to an IRI or to an expanded definition. An IRI is a String: an IRI, a compact IRI such as ="ex:condition"=, or another term. An expanded definition is a record whose keys are among these:

1. =@id=
2. =@type=
3. =@container=
4. =@language=
5. =@direction=
6. =@reverse=
7. =@index=
8. =@nest=
9. =@prefix=
10. =@protected=
11. =@context=

*** Several contexts

Several contexts are written as an array and serialised as one, applied in order, as JSON-LD processes them. A context with one entry is serialised as that entry.

*** Malformed contexts

A malformed context is an error where it is written. It is one of:

- a remote context that is not an absolute URL;
- an unknown =@= keyword;
- a term mapped to something other than an IRI or a definition;
- a key in a definition that is not one of its keywords;
- an array inside the context's array;
- a value with no place in JSON, such as a Date.

Each is a "Malformed Context" error at the context's expression.

*** The key

=:@context= is JSON-LD's own name for the key, and means the same as =:context=. Any other key may also start with =@=, so =:@id= and =:@type= can be written in a record.

A record has one context: writing it twice is an error. A record can hold only a context, ~(:context "https://...")~.

** Surface representation (~S.Expr~)

The parser produces an untyped tree, ~S.Expr~, that mirrors the source. Every node carries its ~SourcePos~, so every later error can point at the exact place in the file.

#+BEGIN_SRC haskell
-- In src/Data/Ouro/Lisp/Surface.hs
data Expr
    = Symbol      SourcePos Text            -- names, functions and special-form heads
    | DefunSymbol SourcePos Text            -- function identifiers (unused by the parser)
    | Literal     SourcePos LiteralValue    -- String, Number, Boolean, empty Array/Record
    | Tagged      SourcePos ReaderTag Expr  -- #uri "...", #date "...", #record (...)
    | Hole        SourcePos Text            -- ?, ?name or ?..name: a placeholder, or in a case pattern
    | Form        SourcePos [Expr]          -- (...)
    | Bracket     SourcePos [Expr]          -- [...], reserved

-- A function's parameter, the property written before it, if any, and the pattern it
-- destructures its argument with, if any
data Param = Param
    { paramName    :: Text
    , paramType    :: Maybe (SourcePos, ReaderTag)
    , paramPattern :: Maybe Expr
    }
#+END_SRC

*** Parameters

A pattern parameter is named by its position, =%arg1=, =%arg2=, ..., which cannot be written in Ouro, so its argument is only reached through the pattern's holes.

~Function.checkParams~ checks the parameters when a function is defined: the parser checks a =define/procedure='s, and the evaluator a =fn='s. Each pattern must bind something, and each name is bound once.

*** Attribute pairs and binders

There is no separate constructor for attribute pairs. The parser reads =:key value= as the form ~(%attr "key" value)~, so a record is a ~Form~ of ~%attr~ forms. =%= cannot be lexed, so the form cannot be written: a key is always written, never computed.

A =$name= is read on its own as ~(%binder "name")~, and paired with its value only inside a =let= (see [[*Desugaring (~Canon~)][desugaring]]).

*** Modules

A module is the parser's other output: a registry of =define/procedure= declarations and a registry of =graph= declarations, each a ~HigherExpression~ indexed by its kind:

#+BEGIN_SRC haskell
data HigherExpression (t :: Declaration) where
    Function :: SourcePos -> Text -> [Param] -> Expr -> HigherExpression 'FunctionExpr
    Graph    :: SourcePos -> Text -> Expr            -> HigherExpression 'GraphExpr
#+END_SRC

A =define/procedure='s return type is applied when it is parsed: its body is stored under the return property, as ~Tagged~. A =fn= is an ordinary form until it is evaluated, where a return property is read from its parameter list, ~(fn #number (n) ...)~.

The parser also enforces the module-level rules:

- imports and the export come first;
- an export names functions of the module;
- two imports cannot share a qualifier;
- a function name cannot be a special form or qualified;
- a function cannot be defined twice;
- a body must be one expression;
- a nested definition is reported with its replacement.

The lexer reports the retired keywords (=defn=, =defn/const=, =defn/property=) and a =define= that names no kind.

** Desugaring (~Canon~)

Before evaluation, ~Canon.canonicalModule~ rewrites every function body and graph into a smaller core by running ~Canon.passes~ in order, one rule per pass. Each pass relies on the ones before it.

*** The passes

| Pass             | Walk      | Rewrites                                                                     |
|------------------+-----------+------------------------------------------------------------------------------|
| 1. placeholders  | top-down  | a call with =?= holes into a function of them                                |
| 2. threading     | top-down  | ~(-> x step ...)~ into nested calls                                          |
| 3. connectives   | top-down  | ~(and a b)~, =or=, and =all= and =any= written in place into a =%case= chain |
| 4. bindings      | top-down  | =$name value= in a =let='s bindings into ~(%bind "name" value)~              |
| 5. guards        | top-down  | a condition, =(when c)=, or a guard ~((< 10) e)~ into a ~(%when c)~ head     |
| 6. contexts      | bottom-up | =:context e= into ~(%context e)~                                             |
| 7. adjoin        | bottom-up | ~(adjoin base item ...)~ into ~(%adjoin base addition ...)~                  |
| 8. with          | bottom-up | ~(with base item ...)~ into ~((%inlay base) item ...)~                       |
| 9. thru          | siblings  | ~(thru (days n))~ into the durations it stands for                           |
| 10. alternatives | bottom-up | a =case= branch ~(("a" "b") e)~ into one branch per literal                  |

In more detail:

- placeholders leave =case= and =fn= patterns as they are;

- in threading, a step with a hole is already a function, by pass 1;

- connectives rewrite ~(and a b)~ into ~(%case #boolean a (true #boolean b) (otherwise false))~, =or= alike, and =all= and =any= over an array written in place into the same chain;

- in guards, a guard names the target, bound once;

- in adjoin, its attribute pairs are grouped into records;

- in thru, as an operand of =+= or =-=, the operation is nested once for each duration.

Nothing is unrolled: every built-in takes a fixed number of arguments, so ~(+ a b c)~ and ~(< a b c)~ are arity errors, and many values are an array, ~(fold xs 0 +)~, ~(all (a b c))~.

*** Walks

A pass walks the tree in one of three ways (~Canon.Traverse~):

- top-down, rewriting a form before its parts, when the rule depends on the form's own shape;
- bottom-up, rewriting a form's parts first;
- over lists of siblings, for a rule that turns one element into several.

An expression that stands on its own is a list of one: a graph's body, or the payload of a property. A =thru= there has no meaning, and is left for the evaluator to report.

*** Order

The order matters in five places:

- threading runs before =adjoin= and =with=, so in ~(-> x (with :k v))~ =with= receives =x= as its base;
- contexts run before =adjoin=, so a context written among its attribute pairs is grouped with them;
- bindings run before =thru=, so a value that expands into several elements stays inside its binding;
- guards run before alternatives, which leave a marked guard alone;
- connectives run after threading, so a step =(and y)= receives the threaded value as its first operand.

Only =thru= walks siblings.

*** Modules

Each pass is a module of its own under =Lisp/Canon/=, with the walks in =Traverse.hs=:

1. =Placeholders.hs=
2. =Threading.hs=
3. =Connectives.hs=
4. =Bindings.hs=
5. =Guards.hs=
6. =Context.hs=
7. =Adjoin.hs=
8. =With.hs=
9. =Thru.hs=
10. =Alternatives.hs=

=Lisp/Canon.hs= is the single entry point: it lists the passes, in order, and runs them, and ~Canon.runPasses~ runs any selection of them. A =define/procedure='s parameter patterns go through ~Canon.patternPasses~, every pass but placeholders, threading and connectives, since a pattern is matched, not evaluated.

*** Sugar and core

| Sugar                                   | Core                                                                |
|-----------------------------------------+---------------------------------------------------------------------|
| a placeholder ~(f ? x ?n #number ?)~    | ~(%fn (%1 ?n #number %2) (f %1 x ?n %2))~                           |
| ~(-> x (f a) g)~                        | ~(g (f x a))~                                                       |
| a function step ~(-> x (h b ?))~        | ~(%apply (%fn (%1) (h b %1)) x)~                                    |
| ~(with base item ...)~                  | ~((%inlay base) item ...)~; ~(with base)~ is ~base~                 |
| ~(adjoin base :k v (inlay x) e)~        | ~(%adjoin base (:k v) x (list e))~; ~(adjoin base)~ is ~base~       |
| =:context e=, =:@context e=             | ~(%context e)~: the record's metadata, not an attribute pair        |
| ~(all (a b c))~, ~(any (a b c))~        | the chain of cases ~(and a b)~ and ~(or a b)~ are                   |
| ~(thru (days n))~                       | ~(days n) (hours 23) (minutes 59) (seconds 59)~                     |
| ~(+ d (thru (days n)))~                 | ~(+ (+ (+ (+ d (days n)) (hours 23)) (minutes 59)) (seconds 59))~   |
| ~(thru (years n))~, ~(thru (months n))~ | ~(years-end n)~, ~(months-end n)~ (resolved against the date)       |
| =case= alternatives ~(("a" "b") e)~     | one branch per literal                                              |
| a =case= guard ~((< 10) e)~             | ~((%when (< %target 10)) e)~, the case bound as below               |
| a condition ~((when c) e)~              | ~((%when c) e)~                                                     |
| a property ~((satisfies #p) e)~         | ~((%when (satisfies %target #p)) e)~, the case bound as for a guard |
| =$name value= in a =let='s bindings     | ~(%bind "name" value)~                                              |

A guard's case, and a property's, is bound as ~(let ((%bind "%target" x)) (case %target ...))~.

- =%adjoin= is a built-in, not a rewrite into =with=, because only the evaluated base says whether it adds attribute pairs to a record or elements to an array.

- A =$name= with no value becomes ~(%bind "name")~ and is reported as having no value. A =$name= anywhere outside a =let='s bindings stays ~(%binder "name")~, and is reported where it is evaluated.

- The =%= heads cannot be written by users.

- =%apply= exists because a form headed by a =fn= is an array, not a call. The evaluator binds the function to a name that cannot be written and calls it with the threaded value, as =map= does for each element.

- Nor can a placeholder's parameter names be written: =%1= cannot be lexed, and =?n= is read as a hole, so a placeholder never captures a name its call refers to.

- A hole left after ~Canon.Placeholders.placeholders~, outside a call's arguments and =case= patterns, is reported where it is evaluated.

** Structural classification

A plain form can be a record, an array or a call. ~determineBlockTarget~ decides which, from the form's contents alone, before anything is evaluated:

#+BEGIN_SRC haskell
determineBlockTarget :: [S.Expr] -> BlockTarget
determineBlockTarget items =
    case items of
        []       -> TargetList
        (x : xs) -> case isFunctionApplication (x : xs) of
                        True  -> TargetFunctionApp
                        False -> case any isStructuralAttr items of
                                     True  -> TargetRecord
                                     False -> TargetList
    where
    isFunctionApplication = \case
        (S.Symbol _ name : _) -> not (isFunctionKeyword name)
        _notAFunction         -> False

    isStructuralAttr = \case
        S.Form _ (S.Symbol _ "%attr"    : _) -> True
        S.Form _ (S.Symbol _ "%context" : _) -> True
        _other                               -> False
#+END_SRC

- *Call*: the first element is a symbol.
- *Record*: otherwise, if any element is an attribute pair or a context.
- *Array*: everything else, including the empty form ~()~.

Only the direct elements of a form matter, never their types: ~(1 "a" (:k 1))~ is an array, because its record has its own parentheses, while ~(1 :a 2)~ is a record with a loose value, which is an error. A record made only of inlays has no written attribute pair, so it is read as an array (see [[*Appendix B: Known gaps][known gaps]]).

Special forms are matched by =evalExpr= before classification, so =let=, =case= and the others never reach it. These rules are why an array beginning with a variable needs =list=.

** Example projection

#+BEGIN_SRC clojure
:timespan (:type               "TimeSpan"
           :identified_by      ((:type    "Name"
                                 :content "40 days in August and September, 1848"))
           :begin_of_the_begin #date "1848-08-01T00:00:00Z"
           :end_of_the_begin   (+ begin_of_the_begin (thru (days 19))))
#+END_SRC

- =:timespan (...)= opens a nested record: its parentheses are the JSON object's braces.

- =:identified_by ((...))= is an array holding one record: the outer parentheses are the array, the inner ones the record.

- =#date= asserts that the string is a timestamp. The value stays a Date inside Ouro, so it can be shifted with =+=, and is written back as an ISO-8601 string.

- =end_of_the_begin= refers to its sibling =begin_of_the_begin=, a binding in the record's own frame. Order does not matter.

* Intermediate Representation and Evaluation

Evaluation turns the surface tree of the selected graph into ~L.Expr~, a value tree that may still contain errors and compile-time-only values. Its design mandates are:

1. *Lexical, lazy, shared:* bindings are promises evaluated at most once, in the scope where they were written.
2. *Value-based:* everything (=get=, patterns, comparison) works on evaluated values, never on code.
3. *Error isolation:* a failure becomes an ~EvalError~ leaf in place, and evaluation of the surrounding tree continues.

** ~L.Expr~

#+BEGIN_SRC haskell
-- In src/Data/Ouro/Lisp/Eval/Types.hs
data Expr where
    -- Frozen targets: already valid JSON-LD
    Primitive       :: I.Expr 'JLD.Primitive -> Expr

    -- Open structure: may contain errors at any depth
    Record          :: I.Expr 'JLD.Meta -> [(Text, Expr)] -> Expr
    Attr            :: Text -> Expr -> Expr          -- an attribute pair, from :k v
    Array           :: [Expr] -> Expr

    -- Compile-time-only values: no JSON form
    Duration        :: PeriodUnit -> Int -> Expr
    PrimitiveOp     :: NativeFunction -> Expr       -- a built-in
    FunctionClosure :: Env -> FunctionId -> [S.Param] -> [S.Expr] -> Expr

    -- The universal error leaf
    EvalError       :: OuroError -> Expr

type NativeFunction = SourcePos -> [Expr] -> Reader Env Expr
#+END_SRC

Records are association lists, ~[(Text, Expr)]~, rather than maps:

1. *Source order is output order*, which keeps serialisation deterministic and the output recognisably shaped like the source.
2. *Errors stay local:* a failed attribute pair is an ~EvalError~ under its own key; its siblings are unaffected.
3. *One linear pass* collects every error in a record.

(Laziness no longer comes from the list: it comes from the promise store, below.)

** The environment model

#+BEGIN_SRC haskell
data Env = Env
    { _localScope       :: Map Text Binding     -- this frame's names
    , _parentEnv        :: Maybe Env            -- the enclosing frame
    , _functionRegistry :: FunctionRegistry     -- functions defined in this frame only
    , _callStack        :: Set FunctionId       -- the functions currently being called
    }

newtype Binding  = Promised Addr               -- every name is bound to a promise
type    Addr     = Int
type FunctionId  = (Text, SourcePos)           -- a function's name and definition position

type EvalM = ReaderT Env (State Store)          -- read the scope, thread the store

data Store = Store
    { _promises  :: IntMap Promise
    , _constants :: Map FunctionId Expr         -- each constant's value, once named
    }

data Promise = Promise
    { _promiseEnv   :: Env                      -- the scope it was written in
    , _promiseExpr  :: S.Expr                   -- its code
    , _promiseName  :: Text
    , _promisePos   :: SourcePos
    , _promiseState :: PromiseState
    }

data PromiseState = Unforced | Forcing | Forced Expr
#+END_SRC

This is the environment model of Scheme (SICP §3.2) with call-by-need bindings, as in Launchbury's natural semantics for lazy evaluation:

- *Frames:* an ~Env~ is a chain of immutable frames. A record, a =let=, a call and a =case= branch each push one frame. The root frame holds the module's =define/procedure= functions.

- *Promises:* every binding is a promise in the ~Store~, which is the only state in the evaluator. ~Reader~ carries the current scope downwards; ~State~ carries the store across, so a promise forced in one place is already forced everywhere else.

- *Functions:* each frame's function registry holds only the functions defined in that frame, so function lookup is lexical too.

- *Built-ins* read the environment only: ~NativeFunction~ runs in ~Reader Env~, never touching the store.

** Evaluation life-cycle
*** Allocating a frame

A record or a =let= is evaluated in two steps:

1. ~collectBindings~ (records) or ~letBindings~ (=let=) sweeps the forms for =:key value= attribute pairs (records) or =$name value= bindings (=let=) and returns their un-evaluated expressions as ~FrameEntry~ values. A local =define/procedure=, a removed form, is reported here.

2. ~allocFrame~ allocates one ~Unforced~ promise per entry and builds the frame that binds their names. Every promise's environment is that same frame, minus the promise's own name. This is what makes the bindings recursive, each binding sees all of its siblings in any order, while a binding never sees itself: its own name resolves in the enclosing scope.

#+BEGIN_SRC haskell
allocFrame :: (Map Text Binding -> Env) -> [FrameEntry] -> EvalM (Env, [Addr])
#+END_SRC

Only a name that the frame binds to that very promise is hidden from it. A function argument's promise closes over the caller's frame, where the same name is a different binding, so it is untouched. A record cannot bind a key twice (that is reported when it is emitted); in a =let=, a name bound twice resolves to the first binding.

*** Forcing

#+BEGIN_SRC haskell
force :: (S.Expr -> EvalM L.Expr) -> SourcePos -> Addr -> EvalM L.Expr
force evaluator refPos addr = do
    promise <- gets (IntMap.! addr)
    case promise ^. promiseState of
        Forced value -> pure value                                  -- shared
        Forcing      -> pure (cyclicLookup refPos (promise ^. promiseName))
        Unforced     -> do
                        setState Forcing
                        value <- local (const (promise ^. promiseEnv))
                                       (evaluator (promise ^. promiseExpr))
                        setState (Forced value)
                        pure value
#+END_SRC

A promise is evaluated in /its own/ environment, not the one where it is referenced: this is what makes scoping lexical. Reaching a promise that is still being forced means the binding depends on itself, which becomes a cycle error instead of an infinite loop.

*** Looking up a name

~lookupVar~ walks outward from the current frame. In each frame it checks the bound names, then the functions defined in that frame, then moves to the parent. At the root it falls back to the built-ins. An unbound name is an error with a "Perhaps you meant" suggestion, ranked by edit distance.

The static analysis (~Lisp.Analysis~) has already resolved every name by the same rules, so a program the evaluator runs has none unbound. What a form is, and what a record, a =let=, a parameter or a hole binds, comes from one module both use, ~Lisp.Analysis.Forms~, so the two cannot disagree about either.

*** Emitting a record

~emitProps~ walks the record's forms again, in source order:

- The record's context, ~(%context e)~, is evaluated like any value, read as a JSON-LD context by ~contextFromValue~, and becomes the record's metadata (~I.Context~).

- An attribute pair is forced through /its own promise/ (found by the position of its =:key=), so an attribute pair that is both output and referenced is evaluated once.

- =inlay= evaluates its expression and splices the resulting record's attribute pairs in place, as a layer: an inlaid attribute pair is dropped when the record writes the same key, or when a later =inlay= has it. Its context is combined under the record's with the metadata =Monoid=, ~inlaid <> rest~, where =rest= already holds the later inlays' contexts and the written one.

- A key written twice, or a second context, is an error at the second occurrence.

- An attribute pair's value must be serialisable (a primitive, record or array; see the [[*3. The Verification Gate][verification gate]]), otherwise the attribute pair becomes an error.

- A loose expression that is not an attribute pair is an error:

  #+begin_example
  Unbound expressions are not allowed inside Record blocks
  #+end_example

Arrays (~compileArray~) evaluate their elements in order, with =inlay= splicing arrays.

*** Calling a function

~evalFunction~ checks arity and recursion, allocates one promise per argument over the /caller's/ environment (under its parameter's property, if the parameter is typed), and evaluates the body in the closure extended with a parameter frame.

A function already on the call stack is called again only from a call the static analysis accepted, the module's ~acceptedCalls~, known by where the function's name is written. Its arguments are forced first, and an error in one is returned instead:

#+BEGIN_SRC haskell
(_, argAddrs) <- allocFrame (const callerEnv)
                     [ FrameEntry (paramName param) (exprPos arg) (typedArgument param arg) False | ... ]
let functionEnv = closureEnv
                & localScope       .~ Map.fromList (zip (map paramName params) (map Promised argAddrs))
                & functionRegistry .~ Map.empty
                & parentEnv        .~ Just closureEnv
                & callStack        .~ Set.insert fnId callerStack
#+END_SRC

Then ~destructure~ forces each pattern parameter's promise and matches it with ~matchPattern~, the matcher =case= uses. The pattern's values are evaluated in the closure, carrying this call's stack so the recursion check holds, rather than in the parameter frame. The holes of every pattern are bound, as already-evaluated values, in one frame between the parameter frame and the body; a value that does not match is reported at its argument.

*** Finishing

~evaluate~ evaluates the graph, then forces every promise that is still ~Unforced~, repeating until none are left (forcing can allocate new promises). The errors found in those values are returned alongside the graph:

#+BEGIN_SRC haskell
evaluate :: Module -> S.Expr -> (L.Expr, [OuroError])
#+END_SRC

Only error leaves count: a binding that holds a Duration or a function is fine as long as it never reaches the output. Forcing a =fn= creates its closure but does not run its body, so an error inside a function that is never called is not reported.

** Error isolation

Ouro does not short-circuit. Each failure becomes an ~EvalError~ at the position where it happened, and the evaluator carries on with the rest of the tree. Operations propagate an error argument rather than failing again, so one mistake produces one message.

Errors are constructed in ~Error.Diagnostics~. Each carries:

- a code derived from its constructor: =SYN=, =TYP=, =SCP=, =INT=, and =WRN= for warnings;
- a message;
- a blurb.

* The Verification Gate

Before anything is serialised, ~validateAST~ walks the evaluated tree and collects:

1. Every ~EvalError~ in the output.

2. Every value that has no JSON form: Durations, functions, built-ins and schema values, reported at the graph's position with the key path to the value (for example ='produced_by.timespan'=).

3. Infinity and NaN, which JSON cannot represent.

4. The errors found in unused bindings, passed in from ~evaluate~.

Errors are de-duplicated (an error in a binding that is also in the output is reported once) and sorted by position. *A graph compiles if and only if this list is empty.*

There are two guards against compile-time-only values. ~emitProps~ checks each record attribute pair as it is emitted, which catches most mistakes with a precise position. ~validateAST~ then checks the whole tree, which also covers the graph root and array elements.

** Type collapse (~freeze~)

A tree that passes the gate contains only ~Primitive~, ~Record~ and ~Array~ nodes. ~freeze~ folds it into the ~I.Expr~ GADT:

#+BEGIN_SRC haskell
freeze :: Expr -> I.Expr 'JLD.Primitive
freeze = \case
    Primitive p -> p
    Record  m p -> I.Record m (foldRecordToGADT p)
    Array     p -> I.Array (foldArrayToGADT p)
    other       -> error ("Invariant: Non-serializable node type: " ++ ...)
#+END_SRC

Building a statically indexed GADT from runtime lists requires an ~unsafeCoerce~ in the bridge to ~I.Expr any~. It is justified by the gate: ~validateAST~ is the lemma that every node is one of the three serialisable shapes. The ~error~ calls in ~freeze~ are internal invariants, not user errors; reaching one means a value bypassed the gate, which is a compiler bug.

* The Internal Model (~I.Expr~)

JSON-LD is represented by a GADT indexed by a promoted kind, so that ill-formed documents cannot be constructed:

#+BEGIN_SRC haskell
-- In src/Data/Ouro/Internal/Kinds.hs
data Type = Primitive | Context | List | Meta

-- In src/Data/Ouro/Internal/Expr.hs
data Expr (t :: JLD.Type) where
    -- Leaves
    String    :: Text    -> Expr 'JLD.Primitive
    Number    :: Double  -> Expr 'JLD.Primitive
    Boolean   :: Bool    -> Expr 'JLD.Primitive
    URI       :: URI     -> Expr 'JLD.Primitive
    Date      :: UTCTime -> Expr 'JLD.Primitive
    Null      ::            Expr 'JLD.Primitive
    BlankNode :: Text    -> Expr 'JLD.Primitive
    EmptyArr  ::            Expr 'JLD.Primitive
    EmptyRec  ::            Expr 'JLD.Primitive

    -- Metadata
    Context   :: Schema -> Expr 'JLD.Meta
    EmptyMeta ::           Expr 'JLD.Meta

    -- The list backbone
    Cons      :: Expr head -> Expr tail -> Expr 'JLD.List
    Attr      :: Text      -> Expr any  -> Expr 'JLD.List
    Nil       ::                           Expr 'JLD.List

    -- Boundary gates
    Record    :: Expr 'JLD.Meta -> Expr 'JLD.List -> Expr 'JLD.Primitive
    Array     :: Expr 'JLD.List                   -> Expr 'JLD.Primitive
#+END_SRC

| JSON-LD                 | Ouro                | ~I.Expr~ constructor    | Haskell type   | Kind      |
|-------------------------+---------------------+-------------------------+----------------+-----------|
| string                  | ="text"=            | ~String~                | ~Text~         | Primitive |
| number                  | =42=                | ~Number~                | ~Double~       | Primitive |
| boolean                 | =true=              | ~Boolean~               | ~Bool~         | Primitive |
| null                    | none: an error      | ~Null~, read by =validate= only | none     | Primitive |
| IRI                     | =#uri "..."=        | ~URI~                   | ~Text.URI.URI~ | Primitive |
| xsd:dateTime            | =#date "..."=       | ~Date~                  | ~UTCTime~      | Primitive |
| blank node              | not yet written     | ~BlankNode~             | ~Text~         | Primitive |
| ={}= / =[]=             | =#record-empty= / =()= | ~EmptyRec~ / ~EmptyArr~ | none           | Primitive |
| node object             | =(:k v ...)=        | ~Record~                | meta + list    | Primitive |
| array                   | =(a b ...)=         | ~Array~                 | list           | Primitive |
| =@context=              | =:context ...=      | ~Context~ / ~EmptyMeta~ | ~Schema~       | Meta      |
| member / attribute pair | none                | ~Cons~, ~Attr~, ~Nil~   | none           | List      |

The indices enforce three boundaries:

- *Leaves are leaves:* primitives are indexed ~'Primitive~ and cannot appear where a list spine is expected.

- *The spine is isolated:* ~Cons~, ~Attr~ and ~Nil~ are indexed ~'List~, so collection mechanics never leak into a leaf position.

- *Metadata has one slot:* the first argument of ~Record~ is the only place a ~'Meta~ value can go, so a context can never be written as an ordinary value.

~Record~ and ~Array~ are the gates that lift a spine back to a ~'Primitive~ value. (The ~Context~ kind is currently unused.)

The context model (~Internal.Schema~) is a context's entries, in order:

#+BEGIN_SRC haskell
newtype Schema = Schema [ContextEntry]        -- Monoid: concatenation, mempty = []

data ContextEntry
    = RemoteContext URI                        -- "https://..."
    | LocalContext  Directives                 -- {...}
    | ClearContext                             -- null

newtype Directives = Directives [(Text, ContextValue)]   -- Monoid: right-biased union

data ContextValue = CString Text | CNumber Double | CBool Bool | CNull
                  | CArray [ContextValue] | CObject [(Text, ContextValue)]
#+END_SRC

*** Contexts are a Monoid under concatenation

JSON-LD processes a context array in order, each entry against the context the earlier ones built, so concatenation is how contexts compose. It is associative, and the empty context, which changes nothing, is the identity. Adjacent local contexts are kept apart, not merged, so each keeps its meaning.

Applying the same entry twice in a row is applying it once, so where two contexts meet, an entry equal to the one before it is dropped: ~[X] <> [X]~ is ~[X]~. Only neighbours collapse: in ~[X, Y, X]~ the second =X= is applied against what =Y= built, so it is kept. The laws hold for contexts built with =<>=, which never hold two equal neighbours.

*** Local contexts are a Monoid under a right-biased union

A key in both keeps the position of its first occurrence and the value of its later one, as defining a term again replaces it. The empty local context is the identity. A local context is built with ~directive key value~ and ~<>~, so each key appears once.

*** A record's metadata is a Monoid too

It is a Monoid over ~I.Expr 'Meta~: two =Context=s combine as their =Schema=s do, and =EmptyMeta= is the identity. =inlay= uses it to layer an inlaid record's context under the record's own.

*** Reading and writing contexts

~Eval.Schema.contextFromValue~ reads an evaluated value as a ~Schema~ and checks it; ~Json.Parser~ reads a JSON =@context= the same way for =ouro validate=, keeping a context array's structure. The serialiser writes a ~Schema~ with one entry as that entry, and one with several as an array.

* The Emission Engine

Serialisation (~Json.Serializer.toJSON~) is a catamorphism over ~I.Expr~: one recursive descent, ~buildJSON~, that emits each node exactly once, in order.

#+BEGIN_SRC haskell
newtype Printer a = Printer
    { runPrinterP :: ReaderT PrinterEnv (StateT PrinterState Identity) a }

data PrinterEnv   = PrinterEnv   { options :: !PrinterOptions, nestingLevel :: !Int }
data PrinterState = PrinterState { activeDirectives :: ![ContextEntry]
                                 , outputBuffer     :: !Builder }
#+END_SRC

- *Reader for layout:* the nesting level flows downwards with ~local~, so entering a structure indents its children without affecting its siblings.

- *State as an append-only buffer:* serialisation is monotonic: output is only ever appended, never rewound. A ~Text.Lazy.Builder~ accumulates it without repeated string concatenation.

- *Strict fields:* the bang patterns on ~PrinterState~ prevent a chain of unevaluated thunks from building up across a deep traversal (the classic lazy-state space leak).

- *Identity at the base:* the stack has no ~IO~. The printer is a pure function from a frozen tree to text; nothing is "run" in a virtual machine.

*** The output

The output is UTF-8 with LF line endings and a trailing newline. Numbers that are whole print without a decimal point.

Strings, keys, URIs and dates are written as JSON strings:

- a quote, a backslash, a newline, a carriage return, a tab, a backspace and a form feed are written as their two-character escapes;
- any other control character is written as a =\u= escape;
- every other character is written as it is.

The same serialiser backs ~ouro validate~, which parses JSON-LD into ~I.Expr~ (~Json.Parser~) and prints it back, as a check that a document is representable.

* Architectural Boundaries
** Module layering

Dependencies flow in one direction, from the pure JSON-LD core upwards:

| Layer        | May import                                                   |
|--------------+--------------------------------------------------------------|
| JSON-LD core | each other only                                              |
| JSON I/O     | the core                                                     |
| Errors       | the core, ~Lisp.Tokens~, ~Lisp.Surface~, ~Lisp.Module.Types~ |
| Front end    | errors, each other                                           |
| Evaluator    | everything below                                             |
| Pipeline     | everything                                                   |
| Command line | the library; nothing in the library imports it               |

The modules of each layer, with =←= for "is imported by":

- *JSON-LD core:* ~Internal.Kinds~, ~Internal.Schema~, ~Internal.Expr~, ~Internal.Utils~.

- *JSON I/O:* ~Json.Parser~, ~Json.Serializer~.

- *Errors:* ~Error.Types~ ← ~Error.Diagnostics~, ~Error.Linter~.

- *Front end:* ~Lisp.Tokens~, ~Lisp.Lexer~, ~Lisp.Surface~, ~Lisp.Function~, ~Lisp.Parser~, ~Lisp.Canon~ (and its passes), ~Lisp.Module.Types~.

- *Evaluator:* ~Eval.Types~ ← ~Eval.Builtins~, ~Eval.Schema~, ~Eval.Pattern~ ← ~Eval.Scope~ ← ~Eval.Structural~ ← ~Eval.Engine~.

- *Pipeline:* ~Data.Ouro~ ← ~Data.Ouro.Build~.

- *Command line:* =cli/=, the internal library =ouro-cli= (~CLI.Project~, ~CLI.Parser~, ~CLI.Runner~, ~CLI.Printer~); =app/= is ~Main~ only.

*Invariants*:

- The JSON-LD core never imports the evaluator: ~I.Expr~ knows nothing about Ouro.

- The front end never evaluates: parsing, rule checks and desugaring work on ~S.Expr~ alone.

- Built-ins and the schema parser only read the environment (~Reader Env~); only ~Scope~, ~Structural~ and ~Engine~ touch the promise store.

- One exception to note: ~Error.Diagnostics~ imports ~Eval.Types~ (to describe values in messages), so the error layer is not entirely below the evaluator.

** Ouro as a structural assembler

Ouro's compiler guarantees structural validity: a compiled graph is well-formed JSON whose values have the types they were asserted to have. It does not resolve vocabularies, fetch remote contexts or check terms against CIDOC-CRM.

- *Justification:* limiting the compiler to structure keeps it deterministic, offline and immune to failures in external Linked Data services.

- *Boundary rule:* URIs are accepted as literal or computed strings, and keys as written literals. Semantic expansion (context resolution, RDF conversion, shape validation) is left to specialised tools after compilation, in keeping with the Unix philosophy.

** Why quoting went

Curators compose and restructure records; they do not manipulate code. Without quoting, code and values cannot be confused, which is what makes the language referentially transparent.

* Appendix C: Benchmarks
:PROPERTIES:

:END:

The benchmarks of each version, as =cabal bench= measured them (=bench/Main.hs=, the =ouro-bench= suite).

Each benchmark compiles a program in memory and renders it as JSON: the whole pipeline after reading the file, lexing, parsing, Canon, the static analysis, evaluation and serialisation. The bundled modules are loaded, and nothing is read from disk while it is timed.

The groups:

- *fixtures:* every fixture of =test/fixtures/ouro/=, linked.art's 211 examples and Ouro's own;
- *hoard:* a generated hoard of 100, 500 and 2000 coins, each built through =std='s constructors.

0.6.0.0 was measured before the two kinds of fixture were joined, so its tables keep them apart, as =canonical= (Ouro's own) and =linked-art=.

Each version is a heading, recorded when the version is released and never changed afterwards. Its drawer holds the date measured, the change measured, the compiler and the machine. Times are tasty-bench's mean, with two standard deviations after =±=, and are comparable only between runs on the same machine.

To record a version:

- =cabal bench --benchmark-options='--csv b.csv'= runs every benchmark and keeps the results as a baseline;
- =cabal bench --benchmark-options='--baseline b.csv --fail-if-slower 20'= compares a later run with it.
